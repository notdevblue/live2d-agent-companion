# Product Requirements Document — Live2D Agent Companion

**상태:** Proposed · **버전:** 0.1 · **기준:** 2026-10-31 · **플랫폼:** Windows 11 우선

## 문제

기존 Grok Bot 앱의 특정 개별 봇 또는 Hermes Agent의 기존 Bot과 대화하려면 별도의 채팅 인터페이스로 이동해야 한다. 사용자는 동일한 봇의 성격·기억을 유지하면서, 데스크톱에 떠 있는 Live2D 캐릭터를 통해 자연스럽게 채팅하고 음성을 듣고, 필요할 때 PC 화면을 보여주거나 안전하게 작업을 맡기고 싶다.

## 제품 원칙

1. **기존 Bot 우선**: 기존 Bot ID/프로필/세션을 유지한다. 새 LLM 대체는 명확히 다른 모드로만 허용.
2. **표현 계층 독립성**: 대화 로직과 Live2D·TTS·행동은 분리한다.
3. **Capability-driven UX**: 공급자가 지원하지 않는 스트리밍/첨부/중단/도구는 UI에서 명시한다.
4. **Local-first**: 데스크톱 표시·렌더·설정은 로컬. 대화는 선택된 공급자로 전송하며, 사용자가 Jev 표현 판단을 켜면 현재 사용자 요청과 표시용 답변의 제한된 구간을 문맥/판단 대상으로 구분해 TypeSafe에 전달한다. 이전 대화·도구 로그는 전달하지 않는다. 공급자 기억/세션은 이관하지 않는다.
5. **권한은 요청 단위**: 화면 읽기와 PC 조작을 분리하고 위험 작업은 승인.
6. **실패 정직성**: Webhook 200을 답변 도착으로 표시하지 않는다.

## 사용자 및 환경

- 기본 사용자: Windows 11 데스크톱에서 장시간 AI 작업을 하거나 대화를 나누는 개인.
- 입력: 텍스트 채팅을 MVP의 주 수단으로, 음성 입력은 후속 선택 기능.
- 출력: 사용자 소유의 Live2D 모델, TTS, 자막/대화창, 상태·승인 알림.

## 목표

- G-01: 하나의 데스크톱 UI에서 서로 다른 에이전트 커넥터 전환.
- G-02: 자연스러운 idle·thinking·talking·working 상태와 TTS 동기화.
- G-03: Hermes 실시간 응답·도구 상태·중단 및 승인 관리.
- G-04: **기존 Grok Bot 연결 가능성 검증**, 성공 시 사용 가능한 텍스트 왕복 구현.
- G-05: 명시적 화면 캡처·승인 기반 PC 조작으로 확장.
- G-06: 장애/지연/지원 한계를 항상 명확하게 전달.

## 비목표(초기 릴리스)

- 새로운 Grok 모델을 기존 Grok Bot으로 사칭하는 동작
- 에이전트 간 대화기록/장기기억 자동 이관 및 자동 혼합
- 24시간 자동 화면 녹화, 백그라운드 몰래 입력, 비승인 원격조작
- VRM/3D 전체 지원, 모바일 네이티브 앱, macOS/Linux 동시 배포
- Live2D 모델 제작·리깅 자동화 또는 모델 자산 재배포
- 공급자 공식 SDK/약관을 우회하는 세션 탈취 방식

## 단계별 릴리스

| 단계 | 사용자 가치 | 완료 조건 |
|---|---|---|
| P0 Foundation | 캐릭터 표시·채팅·Mock 응답 | 투명 창, 기본 모션, 입력/출력, 테스트 |
| P1 Hermes | 실제 에이전트 실시간 대화 | 세션 바인딩, 스트리밍, 취소/오류/승인 처리 |
| P2 Grok Bot | 기존 개별 Bot과의 가능한 연결 | 기술검증 통과 시 기능 활성, 미통과면 명확한 unsupported |
| P3 Expression | 음성·표정·립싱크 | TTS/모션 동기화, 끊기·음소거·fallback |
| P4 Screen | 요청 시 화면을 보여줌 | 선택 범위·미리보기·확인·민감정보 보호 |
| P5 Act | 안전하게 PC 작업 보조 | 도구 권한·사용자 승인·중단·감사 로그 |

순서는 의존성과 리스크에 따라 조정 가능하며 `docs/planning/ROADMAP.md`를 따른다.

## 성공 지표(초안)

- Hermes에서 텍스트 왕복, 인터럽트, 툴 이벤트 UI가 테스트 시나리오 기준 통과.
- Grok Bot에는 성공률을 확정하지 않고 Spike 결과를 기록하며 기능 상태를 사실에 맞게 노출.
- 초기에 60 FPS 목표(지원 하드웨어 및 모델 조건 명시); 사용자 조절 가능.
- 승인 없이 PC 입력·파일 변경·스크린샷 외부 전송이 발생한 횟수 **0**.
- 메시지 전달 실패를 사용자에게 숨기거나 성공으로 표시한 횟수 **0**.
- 응답 지연·메모리·CPU는 기기별 기준선을 실측 후 NFR에 반영.

## 주요 리스크

Grok 양방향 API 부재, 기존 Bot 세션 연속성, Hermes Bot Mode 세션 바인딩, 모델별 리깅 불일치, SDK 라이선스, 공급자 변경, 음성 재생 지연. `docs/planning/RISKS_AND_SPIKES.md` 참조.
