# 사용자 시나리오 및 흐름

## UJ-01 처음 실행

1. 앱 실행 → 투명 캐릭터 창 및 작은 설정 패널.
2. 소유권이 확인된 로컬 `.model3.json` 모델 디렉터리 선택.
3. 모델 호환성 검사(필수 파일·텍스처·표정·모션·파라미터).
4. 에이전트 추가: Hermes 연결 또는 Grok Bot (실험적).
5. 연결 테스트 → 사용 가능 capability와 주의사항 표시.
6. 텍스트 대화 시작. 미지원 기능은 비활성 상태로 설명.

## UJ-02 Hermes Bot와 대화

1. Hermes 호스트/프로필 선택.
2. 기존 Bot Chat 또는 새 일반 세션 중 선택; 기존 Bot Chat 식별이 실패하면 새 세션으로 **조용히 전환하지 않음**.
3. 메시지 전송 → 상태 `submitted → streaming → complete`.
4. 캐릭터는 생각하는 동작 → 답변 읽기 및 립싱크.
5. 승인 요청이 오면 일반 채팅보다 우선하는 모달 표시.
6. 답변 중단 시 오디오와 모션까지 정리.

## UJ-03 Grok Bot와 대화 (조건부)

1. 기존 Bot 및 해당 Bot이 소유한 Webhook Routine을 설정.
2. 전송 버튼 → `accepted / awaiting_result` 상태.
3. 콜백 성공 시 해당 request_id의 답변만 표시하고 TTS 시작.
4. 콜백이 없거나 지연되면 `pending/timeout` 표시; 성공으로 가장하지 않음.
5. 대화 연속성 확인 전에는 '기존 Bot Chat과 동일한 세션'이라고 안내하지 않음.

## UJ-04 에이전트 전환

1. 현재 캐릭터와 음성 재생 상태 확인.
2. Hermes ↔ Grok 전환 시 진행 중 응답 취소 가능 여부 표시.
3. 백엔드 세션/대화 데이터는 공급자별로 분리.
4. 캐릭터 스타일은 프로필별 매핑하거나 글로벌 설정 유지(사용자 선택).
5. 답변이 뒤늦게 도착하면 원래 에이전트 세션에 저장하고 현재 캐릭터 음성으로 끼워 넣지 않음.

## UJ-05 화면 보여주기

1. 사용자가 '화면 보여주기'를 누름.
2. 모니터/창/영역 선택 → 캡처 미리보기.
3. 민감한 내용을 확인하고 '이번 한 번 공유' 승인.
4. 선택된 에이전트의 이미지 지원 여부 확인 후 전송.
5. 미지원이면 전송하지 않고 대안 안내.

## UJ-06 PC 작업 승인

1. 에이전트가 구조화된 로컬 도구 요청(예: 클릭)을 제안.
2. 대상/동작/위험/영향 범위 표시, 승인 또는 거절.
3. 승인 시 짧은 유효기간·범위로 실행, 결과 반환.
4. 실행 과정과 사용자 중단 조작을 상시 노출.
5. 금융·삭제·외부 전송 등 고위험 동작은 추가 확인 또는 차단.

## UJ-07 복구

네트워크 끊김, Hermes 재시작, Grok callback 유실, 음성 출력 장치 변경 시 사용자에게 연결 상태·재시도 가능 여부 표시. 중복 실행 위험이 있는 전송은 자동 재전송하지 않고 명시적 확인을 받는다.
