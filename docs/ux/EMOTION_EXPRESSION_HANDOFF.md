# DeepSeek-chan 감정 연기 구현 인계

**상태:** 기본 경로 구현·검증 · **작성일:** 2026-11-01 · **후속 반영:** 2026-11-02

이 문서는 2026-11-01 인계 범위와 근거를 보존한다. 2026-11-02 사용자 지시로 인계 5개 항목 외에 화남·당황 감정과 선택적 쓰다듬기까지 확장했다. 최신 동작·검증·적용·복원은 [구현 상태](../development/IMPLEMENTATION_STATUS.md)를 따른다. 배경 조사와 파라미터 목록은 [감정 표현 조사](EMOTION_EXPRESSION_AUDIT.md)에 있다. 요구사항의 현재 문장은 `FR-L2D-004`~`007`, `FR-DIR-004`~`005`다. 동작을 바꾸면 해당 명세, 수락 기준, 구현 상태를 같이 고친다.

모델 파일은 `local-assets/DeepSeek/`에만 있고 git에 넣지 않는다. 일러스트는 Kamiya Ryoko, 리깅은 霓虹猫_NeonNeko다.

## 목표

답변이 화면에 있는 동안 얼굴이 그 감정의 여운을 유지하게 한다. 기본 기쁨은 절차적 미소와 눈웃음으로 보이게 하고, 홍조·땀은 눈 아트와 겹치게 한다. 손 포즈는 그 여운이 끝날 때까지 유지한 뒤 복귀 클립으로 돌아온다.

초기 인계 5항목은 감정/호출 수를 늘리지 않는 범위였다. 후속 사용자 지시로 감정은 8종으로 확장했으며 Jev의 질문·호출 수·임계값·본문 한도는 유지했다.

## 인계 시점 동작 (2026-11-01)

한 표시 메시지의 스트리밍은 350ms 뒤 1.8초 끄덕임만 낸다. 의미 판단은 `message.complete`에서 한 번이고, 말투가 중립이 아니면 말투 프리셋이 감정 프리셋보다 먼저 선택된다. 표정 파일은 감정 쪽을 따른다. 반응 길이는 `acting.ts`의 `timing`이다. 끝나면 actor가 반응을 지우고 대기 깜빡임·호흡·작은 시선만 남긴다.

| 프리셋 | 길이 |
|---|---|
| 중립 전달 `acknowledge` | 1.8초 |
| 놀람 | 2.2초 |
| 윙크 | 2.4초 |
| 끄덕임, 도리도리 | 2.6초 |
| 웃음 | 3.6초 |
| 그 외 감정·말투 | 4.2초 |

기본 기쁨 파일은 `model-library.ts`의 `＞＜`(`key5`)다. `avatar.ts`는 `key3`~`key6`이 켜지면 절차적 눈웃음·윙크를 끈다. 그래서 기쁨+웃음은 눈을 감지 못하고 `＞＜`로 보인다. 중립+웃음은 파일 없이 눈을 감는다.

`ExpressionMixer`는 표정 이름 하나다. 홍조 `key7`과 눈 아트는 동시에 못 올라간다. crossfade는 240ms다.

손 포즈는 `PoseSequence`가 진입 클립, 유지, 복귀 클립 순이다. 유지 기본은 1.5초이고 `clamp(holdMs, 400, 2400)`라 2.4초를 넘길 수 없다. 인사에 쓰는 `默认手切举手`는 CDI 이름 抚胸이다. 좌우로 손을 흔드는 곡선은 없다. 이름과 UI 문구를 흔들기로 바꾸지 않는다.

`avatar.ts`의 lean은 `acting.lean * 0.35`다. 기본 강도는 0.65다. 기쁨 프로필 lean 0.16은 화면에서 범위의 약 0.036이다. 고개 끄덕임은 이 계수와 별개로 이미 키워져 있다.

판단 게이트는 Jev 채널 0.65, Director 전체 0.6, 판단 제한 1.5초, 결과 나이 2초다. 이번 작업에서 숫자를 건드리지 않는다.

## 작업 1. 여운 (반영)

강조 동작이 끝난 뒤, 같은 메시지가 최신 반응인 동안 얼굴의 낮은 잔상을 남긴다.

시작값이며 영상에서 잰 값이 아니다.

- 강조는 지금 `timing` 길이를 유지한다.
- 그 뒤 여운은 강조 얼굴의 약 0.4다. 대상은 미소 `ParamMouthForm`, 눈웃음, 눈썹, 미간, 그리고 작업 3의 홍조·땀 층이다.
- 여운 동안 `ParamMouthOpenY`를 범위의 약 0.12로 연다. 놀람 합성은 지금처럼 그보다 크게 둔다. 모음 파라미터와 `JawOpen`은 쓰지 않는다.
- 여운 상한은 12초다. 다음 cue, `cue.clear`, 승인·취소·오류·초기화·새 요청이 오면 상한 전에 걷는다.
- 대기 깜빡임, 호흡, 시선 이동은 여운 중에도 계속한다.
- 강도 ‘차분하게/자연스럽게/풍부하게’와 움직임 줄이기를 여운에도 적용한다. 승인이면 여운도 0이다.
- Jev 호출, 손 제스처 추가, 감정 enum 추가는 없다.

손댈 곳: `src/renderer/acting.ts`의 반응 수명, `src/renderer/performance.ts`의 얼굴 기록, `src/renderer/avatar.ts`의 표정 유지 시간. `reactionDuration`을 그대로 표정 hold로 쓰면 여운이 잘린다.

`clearCue`는 지금 segmentId가 같을 때만 지운다. 여운은 그 clear와 같은 경로로 사라져야 한다. `tests/director.test.ts`의 정정 검사는 판단이 끝나기 전의 clear다. 의미 cue가 이미 적용된 뒤 본문이 바뀌어 `cue.clear`가 오면 여운과 표정과 손이 같이 걷히는지 테스트를 추가한다.

## 작업 2. 기본 기쁨에서 `＞＜` 분리 (반영)

새 인벤토리의 기쁨 기본은 표정 파일 없음이다. 절차적 미소와 눈웃음이 보이게 한다. `＞＜`는 설정에서 사용자가 고를 수 있는 자산으로 남긴다.

`applyModelMappings`는 저장된 값을 우선한다. `settings.expressionMap.happy`가 이미 `＞＜`이면 그대로 둔다. 설정 창을 저장하면 select 값 전체가 파일에 들어가므로, 이 개발 환경에는 이미 그 값이 있을 수 있다. 구현 확인 때 설정에서 기쁨을 ‘기본 연기만’으로 바꾼 뒤 눈웃음이 보이는지 본다. 저장 파일을 코드가 마이그레이션하지 않는다.

`key3`~`key6`이 켜져 있으면 절차 눈을 끄는 규칙은 유지한다. 기쁨+웃음의 자동 경로는 파일이 없을 때 눈을 감는다. 사용자가 `＞＜`를 다시 골랐으면 지금처럼 그 눈이 우선한다.

손댈 곳: `src/main/model-library.ts`, `tests/model-library.test.ts`, 설정 라벨이 빈 기쁨을 오류로 그리지 않는지 `src/renderer/index.ts`.

## 작업 3. 눈과 볼을 두 층으로 (반영)

`ExpressionMixer`를 두 슬롯으로 나눈다.

| 슬롯 | 파라미터 | 규칙 |
|---|---|---|
| 눈 | `key3` `key4` `key5` `key6` | 한 번에 하나. 새 눈은 이전 눈을 교체 |
| 표시 | `key2` 눈물, `key7` 홍조, `key13` 식은땀 | 눈 슬롯과 독립. 서로는 한 반응 안에서 공존 가능 |

자동 연결은 지금 의미를 유지한다. 슬픔은 눈물, 부끄러움·수줍음은 홍조, 걱정은 식은땀, 장난의 첫 변주는 `屑屑眼`. 웃음·기쁨은 눈 슬롯을 비우고 절차 눈을 쓴다. 부끄러움이면서 말투가 웃음이면 홍조 층이 남고 절차 눈웃음이 돌아간다.

옷·소품 키는 어느 슬롯에도 넣지 않는다. 기존 240ms crossfade와 만료 정리는 슬롯마다 유지한다.

손댈 곳: `src/renderer/performance.ts`의 `ExpressionMixer`, `src/renderer/avatar.ts`의 `setExpression`. 테스트는 `tests/performance.test.ts`, `tests/avatar.test.ts`.

## 작업 4. 손 유지 (반영)

의미 반응이 여운을 갖는 동안 그 cue의 손 포즈는 hold에 둔다. 여운이 끝나거나 작업 1의 종료 조건이 오면 지금처럼 복귀 클립을 재생한다. 진입 도중 완성 자세로 점프하지 않는다. 다른 손동작이나 `gesture=none`은 이전 손을 즉시 치우고 중립에서 다시 시작한다. 같은 손의 반복 억제는 유지한다.

`PoseSequence`의 2400ms 상한은 이 유지 시간을 막는다. 상한을 올리되, 상한 없는 영구 토글은 만들지 않는다. 작업 1의 12초 여운 안에 복귀까지 끝나게 둔다.

말투 설명만으로 손을 드는 동작은 추가하지 않는다. 손은 지금처럼 `gesture=wave`와 `gesture=explain`만 시작한다.

손댈 곳: `src/renderer/performance.ts`의 `PoseSequence`, `src/renderer/avatar.ts`의 `startGesture`. 테스트는 `tests/performance.test.ts`, `tests/avatar.test.ts`, `tests/acting.test.ts`.

## 작업 5. 몸 기울임 (반영)

`avatar.ts`의 lean 계수 0.35를 0.7에서 비교한다. 시작값이며 확정 수치가 아니다. 같은 모델, 같은 구도에서 바꾸기 전과 후의 기쁨·장난·슬픔을 렌더해서 기울임이 보이는지 본다. 과하면 0.7과 0.35 사이로 낮춘다.

상하 offset, 호흡 폭, 고개 추적 속도는 이 작업에서 바꾸지 않는다. `前倾` 표정 파일을 자동 연결하지 않는다.

## 완료 조건

- 기쁨 기본(파일 없음)은 강조 뒤 12초 이내의 여운 동안 미소와 눈웃음과 작은 입 열림이 남고, 그 뒤 또는 다음 메시지에서 걷힌다.
- 기쁨+웃음은 `＞＜` 없이 눈을 감는다. 설정에 `＞＜`를 저장하면 그 눈이 우선하고 절차 윙크는 꺼진다.
- 부끄러움+웃음은 홍조가 있는 상태에서 눈을 감는다.
- 걱정 식은땀은 눈 슬롯과 따로 올라간다.
- 설명 손과 인사 손은 여운 동안 hold이고, 끝나면 복귀 클립 뒤 selector와 손목·손가락 endpoint가 중립이다. 다음 메시지의 `none`은 그 손을 바로 치운다.
- 승인·취소·오류·`cue.clear`는 여운과 손을 즉시 정리한다.
- 30/60/120fps에서 같은 시각의 값이 같다. 움직임 줄이기는 여운과 손을 줄이거나 멈춘다.
- 상하 offset 한도, Jev 호출 수, 요청당 8회, physics 출력 보호는 기존 검사와 같다.
- 실제 DeepSeek로 기쁨, 기쁨+웃음, 부끄러움+웃음, 설명 손의 진입·유지·복귀를 한 번씩 렌더한다. 실시간 FPS 측정은 이 완료 조건이 아니다.
- `npm run typecheck`, `npm test`, 해당 변경의 format 검사를 통과한다.

## 확인된 한계

2026-11-01 조사는 모델 JSON과 현재 소스를 읽었다. 이 문서의 시작 계수 0.4, 0.12, 12초, lean 0.7은 그때 새로 렌더해서 고른 값이 아니다. 구현 후 비교 렌더로 조정한다.

같은 세션 14쌍의 재판단은 웃음 9, 중립 전달 4, 인사 1이었다. 설명·슬픔·걱정이 드물게 나오는 판단 정책은 이번 범위 밖이다. 여운을 넣어도 정보 답변의 강조는 1.8초 끄덕임이고, 그 뒤의 잔상만 늘어난다.
