# Grok의 VTuber 연기 검토와 반영 결과

**확인일:** 2026-11-03 · **검토:** Grok CLI 1.0.70 / 기본 `grok-4.7`(실행 사용량의 실제 모델 ID `grok-4.7-build`) · **코드 기준:** `29b85f0` 이후 개선 · **범위:** 무음 시각 연기

사용자는 Grok의 독립 조사·문서 작성, 개선 반영, 새 영상과 재검토를 요청했다. 최종 중지 조건은 Grok의 **100점 만점 평가 85점 이상**이다. 점수는 한 모델의 주관적인 시각 UX 평가이며 일반 정확도·성능·사용성 인증이 아니다. TTS/음성·모음 립싱크는 제외했다.

## 무엇을 실제로 검토했는가

Grok은 먼저 50.4초 앱 시연의 전신/얼굴 filmstrip 16개, 타임라인, 현재 renderer/Director 코드와 구현 상태를 읽고 일반 VTuber/제작자·공식 자료를 조사했다. 이어 사용자가 지정한 [Kamiya Ryoko의 DeepSeek-chan 공식 쇼케이스](https://x.com/kamiya_ryoko/status/2116052617080311882/video/1?s=46)를 같은 모델의 우선 비교 자료로 검토했다. URL은 Grok 추가 턴에 원문 그대로 전달했다.

공식 자료의 익명 공개 메타데이터는 업로더 `kamiya_ryoko`, 게시 2026-10-30, 1280×720, 길이 64.481초다. Grok은 공식 영상의 0.5초 간격 129프레임을 묶은 7개 filmstrip과 추가 확대 프레임 17개를 직접 읽었다. MP4 바이너리의 연속 재생과 음성 동기·트래킹 원인·실시간 FPS는 확인하지 않았다. 영상의 편집 컷/확대/소품 토글을 모델의 실시간 연기와 구분했다.

Grok이 작성한 조사 원문은 로컬 ignored `.tmp/grok-vtuber-review/report/GROK_VTUBER_REVIEW.md`(일반 검토)와 `GROK_OFFICIAL_VIDEO_REVIEW.md`(같은 모델 공식 영상 대조)에 있다. 이 문서는 그 검토를 현재 코드와 대조한 요약·채택 판단·구현·검증 기록이다. 인증키·기존 에이전트 대화·원본 모델/SDK는 Grok 검토 패킷이나 공개 Git에 포함하지 않았다. 전달 자료는 공개 코드/문서와 사용자가 검토를 요청한 영상/렌더 파생물이었다. Grok의 교차 세션 memory는 이 실행에서 껐다. 이 일회성 Grok CLI 검토는 프로젝트의 기존 Grok Bot 앱 Bot/Webhook 연결이나 callback·canonical Bot Chat 연속성의 실증이 아니다.

## Grok의 핵심 지적

일반 검토의 최초 평가는 VTuber다운 생동감 약 3/10, 캐릭터 매력 약 4/10이었다. 이는 시각 샘플에 대한 주관적 평가이고 아래의 후속 고정 100점 기준과 같은 실험 척도가 아니다. 공식 영상 대조의 요지는 **일러스트는 이미 매력적이지만 앱 연기는 표정을 오래 유지하는 상태 표시에 가깝다**는 것이었다.

## 검토 의견을 그대로 적용하지 않은 부분

두 Grok 문서도 서로 다른 제안을 냈다. 일반 검토는 설명 손을 1.6~2.4초 유지로 줄이고 idle 진폭을 키우자고 했고, 같은 모델 공식 대조는 이미 승인된 긴 손 유지와 idle을 보존하면서 얼굴의 짧은 강조·복귀를 먼저 만들자고 했다. 현재 수락 기준과 기존 인계의 의도를 보존하고 같은 모델의 구체적 대조를 우선해, 첫 개선에서는 **손 수명/idle/상하 offset은 유지하고 hold 중 얼굴·고개를 보강**했다. 후속 점수/실제 시각 근거에 따라 다시 판단한다.

일반 검토의 일부 관찰은 원본 렌더 입력과 맞지 않았다. 기쁨·웃음·부끄러움·걱정 시연의 실제 `gesture`는 `none`이고, 손 모션은 설명/인사 입력에서만 시작한다. 해당 영상의 자막도 화남 구간을 ‘불만’이라고 적는다. 따라서 ‘감정마다 양손을 자동으로 올린다’거나 자막이 ‘불안’이라는 해석을 제품 버그로 채택하지 않았다. 최종 재검토에는 실제 cue/gesture와 충분한 전신·얼굴 증거를 함께 제공해 이 오독을 분리한다. 테스트 수나 파라미터 수치를 매력 점수로 바꾸지 않는다.

공식 영상의 안경·냄비·치비 비율·분할 창·자막·회전 편집을 감정 기본값으로 복제하지 않았다. 미확인 `Emotion`/`Emotion2`/`脱捕`와 새 손 포즈/리깅도 연결하지 않았다. 특정 VTuber의 보이스·고유 대사나 사용자 기억/공급자 persona를 바꾸는 작업은 없다.

## 구현과 검증

### 첫 개선 묶음

- `acting.ts`: 기쁨의 약 .8초 반눈, 웃음의 고개 .28 강조와 1회 입 모양 pulse(.35 기준), 웃음 뒤 작은 미소·두 번째 변주의 윙크, 부끄러움+웃음의 시선 회피→지연 웃음을 합성했다. 화남·혼란은 여운에서 입을 열지 않는다.
- 설명 gesture는 약 1.25초 진입 완료와 7.5초 유지 중간에 각각 한 번의 고개/눈썹 beat를 낸다. 종료된 body envelope 때문에 두 번째 beat가 사라지는 원인을 분리했고 해당 beat 구간에서만 기존 빠른 고개 추종을 사용한다. 손 클립·endpoint·복귀와 전체 의미 수명은 보존한다.
- `performance.ts`/`avatar.ts`: 눈 레이어별 짧은 수명과 복귀를 추가했다. 표정 파일과 표시 층의 여운은 별도로 유지하며, 화남은 실제 범위의 음수 입 형태와 지원되는 비-physics 눈썹 입력만 사용한다. 없는 채널/자산 및 authored motion/physics 출력은 건드리지 않는다.
- 쓰다듬기는 기존 입력 규칙을 유지한 채 고개·아래 시선·사용자 홍조를 더한다. 자동 보조 표시에는 `key7`만 허용해 옷/소품이 켜지지 않으며, 이미 적용된 홍조에 더하지 않고 더 큰 기여값을 사용한다. 중단/승인/reset은 기존 경로로 즉시 정리한다.

이는 텍스트를 음소로 바꾼 발화가 아니다. 웃음 한 번의 입 모양 강조만 만들고 반복 모음/턱·오디오·새 Jev 호출은 추가하지 않았다. 강도·움직임 줄이기, 기존 사용자 특수 눈/빈 매핑, 창 위치/배율, 호흡과 상하 offset 한도는 유지한다.

첫 개선의 unit/contract 504개, typecheck 및 실제 모델 수락 검사를 통과했다. 프레임 간격 30/60/120fps, 정확한 수명/승인·취소·clear, 특수 눈 우선, 복합 감정의 시선 순서, 중간 고개 beat, 홍조의 사용자/채널 소유권을 검사한다. 실제 모델에서 얼굴·손·립 형태와 범위를 별도로 확인했으며 실시간 FPS 성능의 통과로 해석하지 않는다.

### 비교 영상과 고정 재검토 기준

비교의 before는 `29b85f0` 시점 4개 renderer 파일의 고정 복사본, after는 각 회차에 묶은 실제 기본 소스다. 같은 모델/normal/bust/합성 입력/20fps로 나란히 렌더하고 source SHA-256과 실제 cue·장면 시각을 결과 JSON에 기록한다. 양쪽 별도 WebGL context의 동일 소스 smoke에서 수치가 같고 GPU 경계 픽셀의 최대 차이는 1/255였다. 원본 모델·영상·frame는 ignored 로컬 근거로만 둔다.

재검토는 새 Grok 세션에서 수행하고 이전 점수나 목표 중지 점수를 제시하지 않는다. 각 회차 같은 0~20점 다섯 항목(감정 가독성, 시간 리듬, 채널 조합/생동감, 캐릭터 매력/변주, 직접 입력 반응)의 정확한 합계를 100점으로 요청한다. 영상의 after에서 직접 추출한 시각 증거로 평가하고, 제외한 TTS 부재·개발 노력·테스트 개수는 점수 근거에서 제외한다. 평가자가 실제 읽은 이미지·모델 ID와 원문 평가를 보관한다.

첫 재검토는 새 세션 `01a19cfc-702c-7d02-bcf5-4f2473b21332`의 `grok-4.7-build`가 수행했다. 평가자는 14개 얼굴 시트와 설명·쓰다듬기·대기·인사 전신 시트 4개를 읽었고, 다른 전신 자료는 읽지 않았다고 명시했다. 가장 좋은 장면은 접촉→홍조→해제 흐름의 쓰다듬기, 가장 약한 장면은 가슴 앞에 손이 고정되는 인사였다. 점수 원문은 ignored `.tmp/grok-grading/round-01-score.md`에 보관한다.

추가 조사에서 원본 CDI의 `Movement2` 이름은 `2. 抚胸`(가슴에 손 얹기)이며, `默认手切举手` 클립도 중간에만 손바닥을 펴고 가슴 위 endpoint로 끝나는 것을 확인했다. 매핑 이름을 wave라고 붙인 것으로 실제 손 흔들기가 되지 않는다. 첫 구현의 ‘인사’라는 해석을 정정하고, 검증된 자산/입력 범위를 사용하는 기본 인사 동작을 별도로 검증한다.

두 번째 재검토는 새 세션 `01a19d0c-1d90-72d3-9895-8d4f5fee05e0`의 `grok-4.7-build`가 **57/100**을 부여했다. 장난 두 번째 변주가 보이지 않고 고개·시선·감정 잔상이 약하다는 지적은 실제 프레임에서도 타당했다. 특히 `concerned + tease` 합성의 고정 눈꺼풀 값이 variant의 wink를 덮는 원인을 찾아 후속 수정한다.

### 두 번째 개선 묶음

### 사용 흐름 영상과 종합 평가 범위
