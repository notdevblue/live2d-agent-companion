## 최근 검토 결과

Grok은 수줍음·직접 접촉·윙크·흰 눈·토라짐을 읽었으나 걱정의 가독성, 기쁨/웃음의 구분, 손 전환을 약점으로 평가했다. 몸이 기본 자세라는 평가는 실제 몸 입력과 기하가 바뀐 사실과 구분한다. 손 좌우 교대 지적도 실제 selector·가시성과 대조해야 하며 그대로 구현 요구로 삼지 않는다.

현재 기본 경로의 설계·채택 이유·책임은 [시각 연기 설계](ACTING_DESIGN.md), 실제 검증·적용·복원은 [구현 상태](../development/IMPLEMENTATION_STATUS.md)를 따른다. 검토 지적을 근거로 새 연출을 자동 적용하지 않는다.

## 평가 방법과 한계

Grok CLI 1.0.70의 기본 `grok-4.7`(실제 모델 `grok-4.7-build`) 새 세션에서 얼굴12·몸35의47페이지 이미지 읽기 완료와 `end_turn`/exit0을 확인했다. 자료는69초·1120×900·20fps·1380 paired frame의 왼쪽 Source20/오른쪽 Source21 비교 영상에서 .5초 간격과 마지막68.95초를 뽑은139표본이다. 저장 profile14·기존59초 입력+10초 무입력 조건을 사용한다.

평가 패킷에는 목표 점수·이전 점수·개발 노력·검사 수와 구현 의도를 미리 주지 않았다. 시각 범위·형식·표본 조건은 유지했지만 이전과 완전히 같은 프롬프트를 반복한 실험은 아니다. 단일 평가의 점수 차이를 코드 효과만으로 해석하지 않는다.

CLI의 MP4 직접 읽기는 지원되지 않아 프레임 자료로 검토했다. [공식 FAQ](https://docs.x.ai/grok/faq#what-file-types-can-i-upload-to-grok)의 웹·앱 MP4 업로드 지원과 CLI 도구를 구분한다. 연속 재생·발화 동기·실제 provider/IPC 대화·실시간 성능·다른 모델/구도의 선호도는 검증하지 않았다. 같은 영상의 재채점은 진행하지 않는다.
