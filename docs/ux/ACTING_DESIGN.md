## 자료에서 확인한 연출 원칙

Live2D 공식 가이드는 얼굴과 몸의 X/Z를 함께 움직이되 관성에 맞게 시점을 어긋나게 하고, 멈출 때 감속과 작은 반동을 줄 것을 설명한다. 시선 전환과 깜빡임의 관계, 표정 변화, 대기와 강조의 크기 대비도 다룬다. 캐릭터에 맞는 움직임을 선택하는 원칙이며 모든 대기 구간을 동작으로 채우라는 지침은 아니다. [공식 모션 가이드](https://docs.live2d.com/cubism-editor-tutorials/motion-hint/)

Cubism에서는 overwrite·add·multiply의 적용 순서가 결과를 바꾼다. 눈 표정 뒤에 overwrite blink를 적용하면 표정의 눈 모양을 잃을 수 있다. 입력 값을 정한 다음 physics와 model update를 거쳐야 실제 변형이 생긴다. 따라서 값의 변화와 화면에서 읽히는 연기를 따로 확인한다. [파라미터 연산](https://docs.live2d.com/en/cubism-sdk-manual/parameters/), [표정 연산](https://docs.live2d.com/en/cubism-sdk-manual/expression/)

여러 motion manager가 같은 입력을 쓰면 뒤에 갱신한 값이 우선하므로 담당 파라미터를 먼저 정해야 한다. VTube Studio도 idle·tracking·one-shot·expression·physics의 우선권과 전환을 명시한다. 앱에는 tracking 대신 로컬 actor가 있으므로 해당 우선순위를 그대로 복사하지 않고 실제 소유자를 정의한다. [Cubism의 부위별 모션 관리](https://docs.live2d.com/en/cubism-sdk-tutorials/multi-motion-management-web/), [VTube Studio의 입력 우선순위](https://github.com/DenchiSoft/VTubeStudio/wiki/Interaction-between-Animations,-Tracking,-Physics,-etc.)

## 같은 모델의 공식 영상 대조

[제작자 쇼케이스](https://x.com/kamiya_ryoko/status/2116052617080311882/video/1?s=46)의64.481초 원본에서0~64초의0.5초 간격129프레임을 담은7개 시트를 메인이 직접 확인했다. 연속 재생이나 발화 동기의 분석은 아니다. 컷·확대·화면 회전·소품 교체는 모델 연기와 구분한다.

| 구간      | 직접 보이는 변화                                            | 앱에 적용할 판단                                   |
| --------- | ----------------------------------------------------------- | -------------------------------------------------- |
| 6.5~7.5초 | 감은 눈에서 눈을 뜨며 얼굴 방향과 시선이 달라짐             | 눈 모양과 방향 전환을 한 반응의 순서로 설계        |
| 13.5~15초 | 열린 눈과 입에서 홍조·감은 눈, 다시 열린 눈과 웃음으로 전환 | 같은 감정에서도 준비와 정점의 표정을 구별          |
| 32.5~35초 | 가슴 손 자세를 유지하는 동안 눈·입·고개가 계속 달라짐       | 손 유지와 얼굴 정지를 같은 상태로 취급하지 않음    |

| 50~51초   | 닫힌 삐친 입과 곁눈질에서 다른 표정으로 전환                | 토라짐의 방향·확인·복귀에 읽을 수 있는 간격을 배치 |

이 영상의 매력에는 일러스트, 리깅, 표정 조합과 편집이 함께 기여한다. 쇼케이스의 컷 수나 확대량을 데스크톱 캐릭터의 상시 움직임 크기로 옮기지 않는다. 안경·치비·의상 등은 자동 감정에 추가할 근거가 아니다.

## 현재 코드에서 확인한 구조

정리 전의 `acting.ts`는 반응 수명, 감정/태도 자세, 얼굴 유지, 시선·blink, 보간을 함께 담당했다. 현재는 [acting.ts](../../src/renderer/acting.ts)가 cue 소유권·시작/승격/중단·시선/blink 일정·보간을, [acting-phrases.ts](../../src/renderer/acting-phrases.ts)가 반응 시간·표정/자세 계산을 담당한다. 기존 `ActingPreset`·`reactionDuration`·`reactionLifetime`의 외부 import 경로는 재노출로 유지한다. 새 계산 모듈은 타이머나 상태를 갖지 않는다.

강조·얼굴 여운·입 복귀는 하나의 `reactionClock`에서 계산한다. 몸·시선·canvas 접근과 paired 손은 기존 강조 구간에 복귀하고, `faceWeight`/`residueWeight`만 최대 .4로 2초 이어진다. 중립 전달에는 여운을 붙이지 않는다. 여운 중 추가 시선 확인·sway·손 유지와 neutral의 별도 sway는 제거했다.

[avatar.ts](../../src/renderer/avatar.ts)는 authored motion, actor, 독립 idle 손/얼굴, 직접 접촉, 표정 자산과 physics를 합성한다. 기존 소유권 차단은 재사용하고 새 감정마다 별도 overlay를 늘리지 않는다. preview와 semantic cue의 눈 강조 우선순위·수명도 한 정책에서 관리하되, 두 모드의 기존 차이를 보존한다.

2026-11-03 사용자 실사용 피드백에 따라 대기 밀도도 낮췄다. 시선은 첫 6초 뒤 강도별 7~20초 간격의 작은 한 번으로 끝나고 정면 휴지로 돌아온다. 자동 눈인사·손은 expressive에서만 8슬롯마다 번갈아 제공한다. 강도는 진폭뿐 아니라 빈도도 조절하고 움직임 줄이기는 간격을 더 늘린다. 이는 아래 Grok 구현·인사의 초기 연기와 소유권을 유지하면서, 과했던 유지 시간과 대기 밀도를 바꾸는 사용자 지시다. 현재 수락·실제 검증은 [구현 상태](../development/IMPLEMENTATION_STATUS.md)를 따른다.

## 모델 자세와 화면 접근의 분리

기존 actor의 `lean`은 실제 `LeanInput`과 canvas MVP의 접근 확대를 함께 바꿨다. 따라서 몸의 숙임을 조절하면 구도도 바뀌어, 실제 자세의 효과와 화면 확대의 효과를 구분하기 어려웠다. Cubism은 모델 파라미터와 표시용 행렬을 별도로 다루며, 이 앱에서도 두 책임을 나누었다. 이는 공식 API가 특정 앱 필드를 요구한다는 주장이 아니라 코드 조사에 따른 설계 결정이다. [모델 표시 위치와 확대](https://docs.live2d.com/en/cubism-sdk-manual/layout/)

`e8cfeb1`에서 `lean`은 rig 자세로 유지하고, `approach`는 canvas 접근으로 명시했다. 기존 프리셋과 접촉은 이전 의도를 두 채널에 동일하게 공급하므로 화면상 동작은 보존한다. 이전 형식의 내부 frame은 `approach`가 없으면 기존 `lean`으로 표시한다. 두 채널 모두 원래 강도/보간·clear를 따르며 움직임 줄이기에서는 기존처럼 canvas 접근을 끈다. 저장 구도·창 위치·배율의 새 설정이나 이관은 없다.

자세와 canvas 접근을 분리한 실제 모델 대조 근거는 ignored `.tmp/approach-separation/`에 있다. 최신 통합 검증은 [구현 상태](../development/IMPLEMENTATION_STATUS.md#감정별-물리-몸-연기-source-21--2026-11-03)를 따른다.

`b33dfda`는 기존 얼굴 흐름과 같은 반응 시계 위에서 몸의 의도를 계산한다. `sampleTorsoIntent`가 기존 독립 상체 분기를 모으고 물리 숙임을 함께 반환한다. 새 owner·이벤트·타이머·랜덤·자동 팔/소품·대기 빈도는 없다.

현재 몸 흐름의 실제 모델·범위·소유권 검증은 [구현 상태](../development/IMPLEMENTATION_STATUS.md#감정별-물리-몸-연기-source-21--2026-11-03)에 모았다. 근거는 ignored `.tmp/response-phrases21/`와 `.tmp/response-concern21/`다. 표본 기하 검사는 모든 중간 프레임의 손 기하나 실시간 FPS 검증을 뜻하지 않는다.

## Grok 구현과 실제 모델 보정

사용자의 별도 구현 요청으로 Grok CLI의 실제 `grok-4.7-build`가 기존 phrase·compositor와 관련 검사를 수정했다. 메인은 실제 Vitest/SDK·MOC와 기본 앱에서 검토·통합한다.

걱정+장난은 처음에 깊은 찡그린 입과 내려간 바깥 눈썹·올라간 안쪽 눈썹을 함께 사용한 뒤, 기존 지연 wink 전에 편안한 표정으로 풀린다. 지원되는 upstream만 사용하고 눈 열림·입 닫힘·기한/감정 여운·매핑은 보존한다. 웃음의 입은 얼굴/몸이 공유하는 `chuckleShape`의 두 박자를 한 번의 연속된 표현 구간 안에서 따른다. 변주의 `accentTime`은 한 번만 적용한다. 기쁨의 작은 미소와 사용자가 저장한 특수 눈은 유지한다. 음소나 음성 시계는 없다.

원본 가슴 손 복귀는 어깨가 거의0인 채 팔꿈치를 펴서 손이 옆으로 나갔다. 메인이 실제 MOC의 어깨/팔꿈치 입력42조합을 정적 대조해, 어깨를 내린 상태에서 팔꿈치를 펴면 손이 몸 가까이 내려오는 것을 확인했다. 직접 접촉과 local idle의 검증된 가슴 손에만 그 경로를 적용한다. 마지막에 그린 enter/hold 입력을 출발점으로 삼고, 팔꿈치의 복귀를 먼저 끝낸 뒤 어깨를 원래 endpoint로 돌린다. 양 끝 기울기와 원래 pose 시계·해제 기한을 유지하며 selector/조명은 원본 clip이 소유한다.

가슴 손 보정은 일반 wave/explain·custom/빈 매핑·reverse-entry·physics 소유 입력에 적용하지 않는다. 인사의 별도 조정은 아래 절을 따른다. none/clear/승인과 다음 pose에서 낡은 손 캐시를 재사용하지 않는다. 실제 검증과 적용·복원은 [구현 상태](../development/IMPLEMENTATION_STATUS.md), 조건은 [수락 기준](../specs/ACCEPTANCE_CRITERIA.md#grok-시각-연기-검토-fr-l2d-009)을 따른다.

## 인사 조정

기준은 사용자가 선택한 **이전 비교 영상의 오른쪽**, 즉 Grok 구현에 메인의 검토·보정을 더한 버전이다. 그 바탕을 유지하고 메인이 인사만 구현했다. Grok은 제공한 공식 원문의 자료 검토만 담당했다. 공식 가이드의 관성·감속·부위별 움직임 대비와 parameter 연산 순서를 근거로 삼되, 손목 중심의 두 번 인사와 관절 좌표는 이 모델의 실제 렌더로 정한 설계다. [모션 힌트](https://docs.live2d.com/cubism-editor-tutorials/motion-hint/), [파라미터 연산](https://docs.live2d.com/en/cubism-sdk-manual/parameters/)

기존 인사는 팔을 옆으로 벌린 .5초 샘플에서 흔들다가 원본 복귀 중간값으로 합류해, 손이 옆으로 뻗는 경로가 남았다. 현재는 검증한 팔 복귀 경로를 역으로 사용해 손을 몸 가까이 올리고, 접힌 팔꿈치로 손바닥을 얼굴 옆에 둔다. 손목의 유한한 두 왕복이 끝나면 조용히 유지한다. 복귀는 실제 hold 시각의 손 자세에서 출발해 원본 exit endpoint로 향하므로 짧은 hold가 흔들기 도중 끝나도 연결된다.

`greetingValues`가 인사 전체를 소유하고 기존 attention은 한 번만 합성한다. custom/다른 pair의 legacy 경로와 설명은 보존한다. 얼굴·눈·입·몸·호흡·canvas 접근·쓰다듬기/대기 손·구도는 이전 오른쪽 버전과 같다. 현재 수락·실행·영상은 [구현 상태](../development/IMPLEMENTATION_STATUS.md)를 따른다.

실사용 시간 조정 뒤 인사 복귀 3.55초에 손끝이 canvas 왼쪽 가장자리에 닿는 회귀를 실제 렌더로 발견했다. 몸이 먼저 정면으로 돌아오면서 기존 팔꿈치/어깨 복귀의 중간 조합이 더 넓게 보였다. 인사 복귀에만 어깨를 낮추는 정점을 복귀의 50%에서 40%로 앞당기고 detour를 80%에 끝낸다. 팔꿈치·원근·손목은 원래 시계를 유지하며 팔꿈치는 기존 75% 시점에 완전히 편다. 기존 `chestArmReturn`을 재사용하며 진입·손 흔들기·전체 기한·양 끝값/기울기·쓰다듬기·custom 경로는 보존한다. 화면 가장자리의 실제 alpha 검사와 근거는 구현 상태 문서에서 구분한다.

## 중복 정리와 후속 이슈

`461079a`에서 기존 `emotionFor`, preview/cue의 눈 강조 정책, 화남의 눈/어깨 확인과 유지 glance 계산을 공통화했다. 검증 없는 테스트 꼬리와 과거 계수 비교용 소스 변조 경로도 제거했다. 모드별 수명·우선순위·실제 출력은 보존했다. 현재 검증·캐시 정리·기본 앱 적용 결과는 [구현 상태](../development/IMPLEMENTATION_STATUS.md#현재-검증과-정리-범위)를 따른다. 회차별 공유/점수/PID 일지는 삭제하고 현재 설계와 근거만 유지한다.

85점 달성을 위한 반복 개선·채점 목표는 **PAUSED**다. 사용자가 별도로 요청한 위 세 항목의 구현과 구분하며, 실제 값·정점 변화만으로 선호도나 점수 상승을 주장하지 않는다.
