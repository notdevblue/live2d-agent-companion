# 시각 연기 설계와 구현 정리

**확인일:** 2026-11-03 · **기준 구현:** `7e89a97` · **범위:** 무음 캐릭터 연기

캐릭터의 준비·강조·유지·복귀를 얼굴·시선·고개·상체가 함께 표현하도록 정리한다. 기존 감정·사용자 매핑·쓰다듬기·중단 경계는 유지한다. 아래 조사와 코드 관측은 메인이 직접 확인했으며, 새 연출의 채택은 실제 모델 비교를 거친다. 현재 Grok 종합 평가는74/100으로85점 종료 조건에는 미달이다. 점수·과거 후보·적용과 복원은 [Grok 검토](GROK_VTUBER_REVIEW.md), 기존5개 인계 항목은 [구현 인계](EMOTION_EXPRESSION_HANDOFF.md)를 따른다.

## 자료에서 확인한 연출 원칙

Live2D 공식 가이드는 얼굴과 몸의 X/Z를 함께 움직이되 관성에 맞게 시점을 어긋나게 하고, 멈출 때 감속과 작은 반동을 줄 것을 설명한다. 시선 전환과 깜빡임의 관계, 표정 변화, 대기와 강조의 크기 대비도 다룬다. 캐릭터에 맞는 움직임을 선택하는 원칙이며 모든 대기 구간을 동작으로 채우라는 지침은 아니다. [공식 모션 가이드](https://docs.live2d.com/cubism-editor-tutorials/motion-hint/)

Cubism에서는 overwrite·add·multiply의 적용 순서가 결과를 바꾼다. 눈 표정 뒤에 overwrite blink를 적용하면 표정의 눈 모양을 잃을 수 있다. 입력 값을 정한 다음 physics와 model update를 거쳐야 실제 변형이 생긴다. 따라서 값의 변화와 화면에서 읽히는 연기를 따로 확인한다. [파라미터 연산](https://docs.live2d.com/en/cubism-sdk-manual/parameters/), [표정 연산](https://docs.live2d.com/en/cubism-sdk-manual/expression/)

여러 motion manager가 같은 입력을 쓰면 뒤에 갱신한 값이 우선하므로 담당 파라미터를 먼저 정해야 한다. VTube Studio도 idle·tracking·one-shot·expression·physics의 우선권과 전환을 명시한다. 앱에는 tracking 대신 로컬 actor가 있으므로 해당 우선순위를 그대로 복사하지 않고 실제 소유자를 정의한다. [Cubism의 부위별 모션 관리](https://docs.live2d.com/en/cubism-sdk-tutorials/multi-motion-management-web/), [VTube Studio의 입력 우선순위](https://github.com/DenchiSoft/VTubeStudio/wiki/Interaction-between-Animations,-Tracking,-Physics,-etc.)

## 현재 코드에서 확인한 구조

정리 전의 `acting.ts`는 반응 수명, 감정/태도 자세, 얼굴 유지, 시선·blink, 보간을 함께 담당했다. 현재는 [acting.ts](../../src/renderer/acting.ts)가 cue 소유권·시작/승격/중단·시선/blink 일정·보간을, [acting-phrases.ts](../../src/renderer/acting-phrases.ts)가 반응 시간·표정/자세 계산을 담당한다. 기존 `ActingPreset`·`reactionDuration`·`reactionLifetime`의 외부 import 경로는 재노출로 유지한다. 새 계산 모듈은 타이머나 상태를 갖지 않는다.

강조·얼굴 여운·몸 유지·입 복귀는 하나의 `reactionClock`에서 기존의 서로 다른 시간 예산을 계산한다. `residueWeight`의 최대값은 .4지만 몸 유지 가중치는1까지 올라간다. 두 값은 역할이 다르므로 하나의 여운 강도로 합치지 않는다.

Source 20 expressive 순수 웃음의 actor 관측에서는0.7초 headZ가.496,1.7초−.030,4초.732였다.4초는 이미 `afterglow`이며 유지 자세가 다시 커진다. 이는 현재 코드의 관측값으로, 실제 화면이 부자연스럽다는 결론까지 입증하지 않는다. 강조와 유지의 관계를 명시적으로 검토해야 하는 근거다. 재현 자료는 ignored `.tmp/direct-research21/actor-phase-audit.mjs`와 JSON에 있다.

[avatar.ts](../../src/renderer/avatar.ts)는 authored motion, actor, 독립 idle 손/얼굴, 직접 접촉, 표정 자산과 physics를 합성한다. 기존 소유권 차단은 재사용하고 새 감정마다 별도 overlay를 늘리지 않는다. preview와 semantic cue의 눈 강조 우선순위·수명도 한 정책에서 관리하되, 두 모드의 기존 차이를 보존한다.

## 정리와 변경 순서

1. 기존 동작을 바꾸지 않고 반응 시간과 중복 정책부터 정리한다.192조합·변주·강도·접근성·30/60/120fps·수명/clear를 기존 구현과 비교한다. 이 단계만으로 매력 개선을 주장하거나 같은 영상을 재채점하지 않는다.
2. 정리한 시간 모델 위에서 감정별 준비·정점·안정·복귀를 정의한다. 큰 값 하나를 더하기 전에 시선의 대상, 몸의 의도, 감정이 바뀌는 시점을 설명할 수 있어야 한다.
3. 실제 MOC에서 구도·매핑·입력을 고정해 전체 동작을 비교한다. 단일 정지 화면의 정점 차이만으로 채택하지 않는다. 보간과 physics가 남기는 복귀 잔차도 확인한다.
4. 기본 실행 경로에 통합하고 unit·SDK·native 재실행·설정 보존과 결과 영상을 검증한 뒤 Grok의 독립 검토를 받는다.

TTS·가짜 음소·전역 커서·새 자산·자동 authored 팔은 이 정리에 추가하지 않는다. ambient 호흡/rootY·창 위치·저장 배율과 기존12초 여운 상한도 유지한다.

## 기존 산출물 관리

생산 코드와 재현 가능한 검증 스크립트를 기준 경로로 삼는다. 회차별 렌더·소스 해시·완료 점수·실패 근거는 ignored 증거로 보존하고, 채택하지 않은 실험은 기본 코드에 합치지 않는다.20차 이후의 윙크/화남 보조 후보는 독립 조사·구조 정리를 마칠 때까지 보류한다. 재현용 원본·파생 프레임·재생성 가능한 캐시를 구분해 보관하며, 공개 저장소에는 모델·SDK·원시 세션을 넣지 않는다.
