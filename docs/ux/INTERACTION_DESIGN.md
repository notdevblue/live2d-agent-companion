# UI/UX 및 캐릭터 상호작용 설계

**상태:** Proposed

## 화면 구성

1. **Character Overlay:** 평소에는 투명 배경에 Live2D 모델만 표시. 테두리·제목 표시줄·패널·상시 핸들을 두지 않고 모델을 잡아 이동한다. 상태 아이콘/조작 UI는 사용자 호출 시 표시하고 클릭 통과는 별도 지원 검증.
2. **Chat Panel:** 텍스트 입력, 메시지/자막, 보내기/취소, 첨부, 입력 중 표시.
3. **Agent Switcher:** 공급자 아이콘, 연결 상태, 봇 이름, 현재 세션, capability.
4. **Action Panel:** 진행 중 도구·요청된 승인·보류된 작업·중단 버튼.
5. **Settings:** 모델 경로·표정 매핑·음성·공급자 연결·프라이버시/권한.

Chat Panel/Action Panel/Settings는 필요할 때 별도 창으로 열어 모델 단독 표시를 유지한다. 특히 승인 창은 클릭 통과 없는 안정된 입력 영역과 포커스를 확보한다. Overlay와 별도 채팅/설정 창은 구현되어 있으며 플랫폼별 검증 범위는 [구현 상태](../development/IMPLEMENTATION_STATUS.md)를 따른다.

Linux에서는 채팅·설정 창을 관리되는 `dialog`로 생성해 Sway/Xwayland에서 자동으로 floating 처리한다. 모델 창의 항상 위 동작과 별개이며, 입력 포커스는 유지한다. 별도 Sway 규칙 없이 새 창 생성·앱 재실행 때 같은 방식이 적용된다.

채팅·설정·승인 팝업은 사용자 현재 rice의 **Yuru** 팔레트(배경 `#1E191F`, 면 `#2A222B`, 크림 `#E1DBD1`, 민트 `#88D4CC`, 버건디 `#712F3E`)를 사용한다. 입력·버튼·말풍선은 직각 1px 경계이며 한영 글꼴은 Sarasa Mono K, 미설치 환경은 Ubuntu Mono/Noto CJK/monospace로 fallback한다. 키보드 포커스·선택·경고/오류·비활성 상태도 구분한다. dark color-scheme은 `#chat` 안에만 적용해 모델 Overlay의 root/배경 투명을 유지한다. CSS 변수와 main 창의 첫 paint 배경에 저장된 테마이며 OS rice의 후속 변경을 자동 감시하지 않는다.

표정·모션 매핑 목록은 DeepSeek 자산의 한국어 표시명을 사용한다. 원본 이름은 항목의 tooltip으로 확인하며 저장값과 파일 이름은 변경하지 않는다. 의미를 확인하지 못한 `脱捕`는 ‘특수 동작 (원문: 脱捕)’로 표시하고, 번역이 없는 다른 모델 자산은 원문을 유지한다.

## UI 플로우와 의미

| 상태 | 표시 문구 예시 | 캐릭터 |
|---|---|---|
| disconnected | 연결되지 않음 | idle |
| connecting | 연결 중 | idle |
| submitted | 보내는 중 | thinking |
| accepted (async) | Grok Bot이 요청을 받음 · 답변 대기 | thinking |
| streaming | 응답 작성 중 | thinking → talking(음성 재생 시) |
| tool.started | 작업 진행 중 · 자세히 보기 | working |
| approval.requested | 승인 필요 · 실행 전 확인 | neutral, 제스처 중단 |
| completed | 답변 완료 | talking → idle |
| reconciling (disconnect/timeout) | 원격 실행 상태 확인 중 · 같은 세션 전송 보류 | error → idle |
| failed | 요청 실패 확인 · 재시도 가능 여부 표시 | error → idle |
| unsupported | 이 연결은 해당 기능을 지원하지 않음 | idle |

'보내기 성공'과 '답변 완료'는 서로 다른 상태. 특히 Grok Bot의 callback 미도착은 성공으로 표시하지 않는다.

## 캐릭터 상호작용

- 클릭: 기본 표정 반응(옵션), 앱 포커스 및 채팅 열기.
- 왼쪽 드래그: 모델을 잡아 모니터 사이로 자유롭게 이동. 버튼을 놓거나 capture가 취소되면 이동을 종료한다. 화면 경계에 붙잡거나 창 전체를 화면 안으로 밀어 넣지 않는다.
- 드래그 중 휠: 잡은 지점을 기준으로 배율 조절. 화면 밖에 일부를 둔 위치·배율도 재실행 후 복원한다. 크기 조절을 클릭으로 처리해 채팅을 열지 않는다.
- 모니터 선택: 채팅 창의 ⚙ → 캐릭터 → 모니터 선택 → ‘선택한 모니터로 이동’. 연결된 모니터의 이름/크기와 현재 위치를 표시하며, 이동은 대화 연결과 별도로 즉시 저장한다. 가장자리 밖으로 내보낸 분량도 유지한다.
- 상반신 표시: 캐릭터를 화면 아래로 내려 하반신을 밖에 둔다. 일부라도 연결된 화면과 겹치면 위치를 유지하고, 완전히 사라졌을 때에만 시작/드래그 종료/모니터 제거 시 기본 화면으로 복구한다.
- 빈 영역: 클릭 통과를 켠 경우 뒤쪽 창에 입력 전달. 모델로 다시 진입하면 클릭/드래그를 복원하고 드래그 중에는 클릭 통과를 끈다.
- 위치 복구: 트레이 또는 `Ctrl+Shift+Home`. 채팅/설정은 모델 클릭·트레이 또는 `Ctrl+Shift+Space`로 연다.
- 마우스 바라보기: 사용자 ON/OFF 및 움직임 완화 옵션.
- idle: 눈 깜빡임/호흡/미세한 움직임. 과도한 시선 추적·음성 자율발화는 기본 비활성화.
- speaking: TTS 실제 출력 시간에 립싱크.
- working: 원격 도구 상태를 표현하되 사용자의 PC에서 실제 조작 중이라는 오해가 없도록 텍스트와 함께 표시.
- approval: 캐릭터 애니메이션보다 승인이 우선, 수락/거절의 클릭 영역이 안정적이어야 함.

2026-10-31 사용자 지정 레퍼런스는 Steam의 [your wife](https://store.steampowered.com/app/3339420/your_wife/?l=english)다. 공식 설명에서 왼쪽 드래그 이동, 드래그 중 휠 확대/축소, 마우스를 바라보는 동작을 확인했다. 이번 조작 수정에는 이동·휠 배율을 반영한다. 시선 추적과 전체 모델 입력 잠금은 후속 설계로 남기며, 게임을 직접 실행해 검증한 결과는 아니다. Windows의 `Win+Shift+방향키` 모니터 이동 안내는 Sway 단축키로 그대로 적용하지 않는다.

## 구현된 캐릭터 연기와 표현 설정

2026-10-31 사용자 후속 지시로 아래 기능을 구현했다. `캐릭터 우클릭 → 설정 → 캐릭터`에서 연출 강도(조용함/기본/과장), 전신/상반신/얼굴 근접 구도, 위치 잠금, 움직임 줄이기를 바꾸면 즉시 저장한다. 대화 provider/session과 Overlay renderer를 유지하며 구도는 canvas 안에서만 바뀐다. 기존 모니터 위치·배율·화면 밖 잘림·항상 위/모든 작업공간 선택을 바꾸지 않는다. 위치 잠금 중에도 모델 클릭으로 채팅을 열고 명시적 모니터 이동·위치 복구를 사용할 수 있다.

생각/설명/쑥스러움/장난/기쁨 미리보기와 초기화는 로컬 연출 전용이다. 실제 요청·승인 중에는 비활성화하고 main에서도 거절한다. 미리보기가 실제 첫 cue의 cooldown을 소모하지 않는다. 머리/시선/몸의 시간차 반응, 비주기 blink, 표정 crossfade, DeepSeek 손동작의 진입·유지·복귀를 제공한다. 손 포즈는 손목·손가락의 authored endpoint까지 유지한다. reduced motion은 연속 움직임을 줄이고 손 제스처를 중단한다.

Jev는 기존 한 요청에서 emotion/gesture와 함께 선택적 attitude(`neutral/explain/tease/laugh/shy/reassure`)를 판단한다. 함께 웃는 농담은 laugh, 상대를 능청스럽게 놀리는 말투는 tease로 구분한다. 장난에는 로컬에 존재할 때 `屑屑眼`, 쑥스러움에는 사용자 embarrassed 매핑을 사용한다. 설명 말투만으로 손을 들지는 않으며 명시적인 설명 gesture만 손 포즈를 시작한다. Jev 비활성화/호출 예산 소진 뒤에도 로컬 중립 전달 반응을 유지한다. 자동으로 선택되는 표현과 미리보기 전용 표현은 [전체 표현 점검](../integrations/LIVE2D_TTS.md#전체-표현-점검-2026-11-01)을 따른다. 공급자 답변·기억을 수정하거나 새로운 대사를 생성하지 않는다. 구체 검증 범위와 한계는 [구현 상태](../development/IMPLEMENTATION_STATUS.md)를 따른다. TTS·립싱크·마우스 시선 추적·쓰다듬기·새로운 리깅 제작은 구현하지 않았다.

채팅 메시지 하나에 대표 표정 하나만 적용한다. 문장별 큐와 애니메이션 종료 대기를 없애고 새 메시지의 표정은 바로 이전 반응을 바꾼다. 첫 문장/충분한 본문/완료 시 800자 이하로 판단하며, 아주 짧은 스트림은 최대 350ms만 모은다. 요청당 최대 8회·판단 timeout/2초 나이 한도를 적용하고 새 메시지/중단/승인/복구는 이전 미적용 판단을 취소한다. 동일 감정의 새 메시지에는 제한된 시선/눈웃음 변주가 가능하지만 같은 메시지를 다시 재생하지 않는다. Hermes가 실제로 보낸 중간 응답과 최종 답변은 서로 다른 말풍선이며, 확인한 사실과 다음 단계를 짧게 보고하도록 앱 요청에만 안내한다. 모델이 진행 보고 빈도를 보장하는 것은 아니다.

채팅에서는 직접 전송하면 하단으로 이동하고, 답변을 따라가다가 위로 스크롤하면 과거 메시지를 읽는 위치를 유지한다. assistant의 Markdown 문단/강조/목록/코드/표는 실시간과 복원 이력에서 같은 경로로 렌더링하며 user 입력은 원문이다. 긴 코드·표는 bubble 내부에서 스크롤하고 링크/이미지는 외부 이동·자동 로드 없이 표시한다.

### 기본 표정·모션 매핑

DeepSeek 기본 연결은 아래와 같다. 모델에는 전용 생각 모션/놀람 표정 파일이 없어 기존 로컬 연기와 지원되는 얼굴 파라미터를 사용한다. 소품·의상 전환이나 의미 미확인 모션을 빈 항목에 대신 연결하지 않는다.

| 항목 | 기본 연결 |
|---|---|
| 중립 | 모델 기본 표정 |
| 기쁨 | 눈 꼭 감기 (`＞＜`) |
| 슬픔 | 눈물 (`流泪`) |
| 놀람 | 놀람 (기본 표정): 눈·눈썹·입 파라미터 합성 |
| 부끄러움 | 홍조 (`脸红`) |
| 걱정 | 식은땀 (`流冷汗`) |
| 손 흔들기 | 손 들기 → 유지 → 기본 손 (`默认手切举手`) |
| 설명 | 검지 포즈 → 유지 → 복귀 (`竖手指切出来动画`) |
| 생각 | 생각 (기본 연기): 시선·고개 기울이기 |
| 제스처 없음 | 추가 모션 생략 |

설정의 ‘생각 (기본 연기)’와 ‘놀람 (기본 표정)’도 저장·복원 가능한 선택지다. 다른 자산으로 바꾼 생각 모션은 미리보기·응답 대기 진입·Jev gesture에 함께 적용한다. 중립/없음과 ‘기본 연기만 (추가 자산 없음)’은 미설정 오류가 아니라 추가 자산을 쓰지 않는 선택이며 기존 로컬 연기는 유지한다.

`캐릭터 우클릭 → 설정 → 캐릭터`의 기존 연기 미리보기에 **놀람, 윙크, 끄덕끄덕, 도리도리, 볼빵빵·삐짐, 눈웃음, 하트 눈, 강아지풀**을 추가한다. 하트 눈/소품은 대응 자산이 있을 때 사용한다. 자산이 없으면 로컬 시선/고개 연기만 하고 실패하지 않는다. 자동 응답에는 기존 Jev의 emotion/gesture/attitude 결과를 그대로 재사용하며, 이 취향 동작을 판단하려고 새 LLM 호출을 직렬로 추가하지 않는다. 하트 눈/삐짐/강아지풀은 우선 명시적 로컬 미리보기로 제공한다.

새 동작도 기존 연기 강도/움직임 줄이기와 승인·취소 차단을 따른다. 특수 눈 자산(`key3~key6`)이 켜지면 procedural wink를 중첩하지 않는다. 눈 blink는 놀람 눈 배율과 곱해 닫히는 순간을 보존한다. 이전 사용자가 줄인 전체 모델의 상하 offset 한도는 올리지 않는다. OS 창 위치·크기·모니터·구도·대화 공급자/세션을 자동 연기로 바꾸지 않는다.

후속으로 가치가 있는 항목은 선택적 커서 시선, 사용자가 부르는 쓰다듬기 반응, TTS 시간에 맞춘 발화 연기와 립싱크, 키보드/게임패드·새 손가락 리깅이다. 이들은 각각 입력 동의·조작 충돌·오디오 시계·추가 모델 자산이 필요하므로 이번 얼굴/고개/기존 손동작 범위와 구분한다. 영상의 입 움직임을 음성 없는 가짜 발화로 옮기지 않는다.

### 움직임의 세 범위

1. **배치:** OS Overlay의 위치/크기. 사용자가 정한 모니터, 화면 밖 잘림, 항상 위·모든 작업공간 표시를 보존한다. 자동 감정 연기가 창을 다른 모니터로 옮기거나 저장 위치를 덮어쓰지 않는다.
2. **구도:** canvas 안의 모델 이동/배율/회전. 전신·상반신·얼굴 근접 프리셋과 일시적인 전진/후퇴를 담당한다. 저장한 기본 구도와 일시 연출 offset을 나누고 끝나면 기본 구도로 복귀한다. 조사 시점에는 이 독립 구도 계층이 없었고 후속 구현에서 canvas 구도를 추가했다.
3. **연기:** 시선·고개·몸·눈썹·눈꺼풀·입 모양과 기존 physics. 전체 창을 흔드는 것과 모델 안의 고개 끄덕임을 구별한다.

VTube Studio 공식 [모델 설정](https://github.com/DenchiSoft/VTubeStudio/wiki/VTS-Model-Settings)은 head position 기반 좌우/거리 이동과 위치·회전·크기·전환 시간을 저장하는 Move Model hotkey를 제공한다. [시작 안내](https://github.com/DenchiSoft/VTubeStudio/wiki/Getting-Started)는 위치 잠금이 face tracking까지 끄지는 않는다고 구분한다. 우리 앱도 **배치 잠금과 표정/연기를 독립 옵션**으로 설계한다. VTube Studio를 이 프로젝트에 연결하거나 카메라를 켠 것은 아니다.

### 개선 전 구현과 DeepSeek 자산 감사

- `src/renderer/avatar.ts`: 고정 4.4초 blink, sine breath, thinking/working 공통 tilt, 한 개의 4.2초 expression, 1.6초 cooldown의 단발 gesture다. 새 표정은 이전 표정 목록을 교체하고 새 gesture는 기존 motion을 중지한다. 복합 표정·시선·연기 sequence·pose hold/release·구도 전환은 없다.
- `src/core/character-director.ts`: 결정적 idle/thinking/working/error와 비동기 Jev 판단을 분리한다. 문장/최대 800자 구간에서 최신 판단만 적용하며 timeout 기본 1.5초, confidence 기준 .6이다. 빠른 구간이 앞선 판단을 취소하므로 답변 전체의 순차 연기 계획은 아니다.
- DeepSeek는 로컬 JSON 기준 parameter 509개, expression 23개, motion 8개, physics settings 131개다. 이름/수치 확인은 실제 연출 품질 확인과 별개다.
- **구동 경로 주의:** physics는 `AngleX/Y/Z`를 입력받아 `ParamAngleX/Y/Z`를 100% weight로 출력한다. 지금 thinking tilt는 physics 전에 `ParamAngleZ`를 수정하므로 덮일 수 있다. 모델 프로필에서 `Angle*`, `Position*`, `LeanInput` 등 upstream과 범위/중립값을 매핑하고 기존 physics를 통과시켜야 한다. 직접 머리카락/꼬리 physics 출력에 sine를 더하는 방식은 피한다. [공식 Cubism 갱신 예제](https://docs.live2d.com/en/cubism-sdk-manual/parameters/)와 [VTS 우선순위 설명](https://github.com/DenchiSoft/VTubeStudio/wiki/Interaction-between-Animations,-Tracking,-Physics,-etc.)도 덮어쓰기 가능성을 설명한다. 두 제품의 적용 순서를 그대로 동일시하지는 않는다.
- 기존 `IDLE`은 5.983초이며 특수효과 보조 curve 위주라 풍부한 일상 자세 연기를 대신하지 않는다.
- `默认手切举手`/`举手切默认手`는 1.133/1.017초의 `Movement2` 진입/복귀 쌍이다. CDI에는 抚胸(가슴에 손 얹기)로 적혀 있어 현재 의미 이름 `wave`와 일치하는지 시각 검증이 필요하다. 손 흔들기로 검증되었다고 부르지 않는다.
- `竖手指切出来动画`/`竖手指切回默认`는 각 1.25초의 설명 포즈 진입/복귀 쌍이다. `狗尾草切换出来`/`狗尾草切回默认手`도 소품 포즈 쌍이다. 자동으로 한 파일만 재생하기보다 진입→짧은 유지→복귀로 구성할 수 있다.
- `脱捕` 13.15초 모션의 실제 내용과 적절성은 미리보기 전 미확정이다. 자동 연기에 연결하지 않는다.
- 활용할 expression 후보: `脸红`(홍조), `屑屑眼`(장난스러운 눈), `＞＜`, `圈圈眼`, `流冷汗`, `加载`, `前倾`, `竖食指开`. 파일이 존재한다는 뜻이며 조합 결과가 검증됐다는 뜻은 아니다. 현재 대부분 Add이므로 같은 눈 형태는 배타, 홍조/땀 등은 호환 조합으로 검토한다. 옷/체형/소품은 감정 기본값과 분리한다.

| 구도 | 상반신 기본 구도 및 별도 근접 연출 | 자동 재생 중 구도 고정. 사용자 드래그/배율·부분 오프스크린 배치만 지원 |

손 자산에 대한 앞선 이름 기반 추정을 보완한다. 실제 렌더에서는 현재 `wave`가 팔을 밖으로 내밀어 손바닥을 보이는 포즈, `explain`이 손가락을 내미는 포즈로 나타난다. CDI의 抚胸라는 이름만으로 wave 매핑이 틀렸다고 확정하지 않는다. 현재 부족한 점은 반복 손 흔들기, 자세 유지, 복귀 자산 연결, 시선/고개와의 결합이다. 손이 갑자기 원점으로만 순간 이동하는 것도 아니다. 현재 고정 fade-out으로 기본값에 돌아오지만 별도의 복귀 자산을 사용하지 않는다.

이 비교에서 가장 먼저 해결할 묶음은 **physics upstream 구동 + 표정 전환 + pose 진입/유지/복귀**다. 그 다음 시선과 고개를 연기 프리셋에 연결해야 기본 생동감과 짧은 과장을 함께 만들 수 있다. 제품 코드는 이 조사에서 수정하지 않았다.

### 캐릭터다운 연기 프리셋 제안

| 상황 | 짧은 연기 구성 | 현재 자산/추가 작업 |
|---|---|---|
| 생각 중 | 시선을 위옆으로 피함 → 작은 갸웃 → 답변 시작 때 정면 복귀 | upstream angle·eye mapping, 상태 시작 즉시 로컬 실행. Jev 대기 불필요 |
| 설명/자신 있음 | 정면 주시 → 손가락 포즈 진입 → 요점 동안 유지 → 손 복귀와 작은 끄덕임 | 기존 `Movement3` 진입/복귀 재사용; hold·취소 정책 추가 |
| 쑥스러움 | 홍조 → 시선 피하기/고개 약간 내리기 → 잠시 후 정면으로 힐끔 | `脸红` + eye/head sequence. 매번 모든 동작을 켜지 않음 |
| 장난/도야가오 | 반쯤 감긴 장난스러운 눈 → 작은 고개 기울임 → 잠깐 가까워짐 → 복귀 | `屑屑眼` + 작은 구도 offset; 큰 확대는 사용자 연출 강도 설정에 따름 |
| 기쁨/성공 | 눈웃음 또는 `＞＜` → 짧은 끄덕임/작은 몸 반동 → 미소만 잠시 유지 | blink·눈 형태 충돌 해결, repetition 억제; 하트눈은 일반 성공에 남용하지 않음 |
| 당황/에러 | 짧게 굳음 → 시선 이동/작은 후퇴 → 땀 → 중립 복귀 | `流冷汗`; error 표현은 연결 오류 문구와 함께, 장시간 떨림 금지 |
| 직접 상호작용 | hover에 짧게 관심 → 사용자가 쓰다듬기를 선택한 경우 눈웃음 → 놓으면 부드러운 복귀 | 지역별 hit zone 미구현. 클릭=채팅, 드래그=이동과 충돌하지 않는 별도 동작/옵션 필요 |

‘십덕력’은 새 감정 이름 수보다 **캐릭터가 상황을 받아들이는 습관**으로 만든다. 예를 들어 기쁠 때 즉시 크게 뛰기보다 눈웃음→작은 자랑, 부끄러울 때 홍조만 켜기보다 시선 회피→다시 보기로 구성한다. 조용함/기본/과장 강도, 반복 억제, 낮은 빈도의 희귀 반응을 제공하되, 장면마다 랜덤 표정을 섞지는 않는다. 특정 버튜버의 고유 대사/행동이나 목소리를 복제할 필요는 없다.

### Jev와 로컬 Director 역할

기존 비동기 분리를 유지한다. Jev는 허용된 의미/태도 preset만 선택하고, 로컬 Director가 준비→강조→유지→복귀와 각 parameter를 결정한다. 매 프레임 외부 판단을 요청하지 않는다.

- 1차는 기존 emotion/gesture 결과를 로컬 preset으로 풍부하게 해석한다. 계약을 늘리기 전에 기존 판단만으로 개선 가능한 부분을 검증한다.
- 후속으로 `attitude = neutral | explain | tease | shy | reassure` 같은 제한된 Choice를 검토한다. 슬픈 내용을 설명한다고 캐릭터도 울게 하는 등 **문장 주제의 감정과 말하는 태도**를 혼동하지 않도록 한국어 fixture를 평가한다.
- `confidence`는 판단의 불확실성이고 감정 강도가 아니다. 그대로 홍조/몸 흔들림의 amplitude로 사용하지 않는다. 강도가 필요하면 별도 검증된 필드 또는 로컬 규칙을 사용한다.
- 모든 문장마다 포즈를 바꾸지 않고 최근 적용 preset, 최소 유지 시간, 최신 구간과 나이 제한으로 coalescing한다. 아주 짧은 주요 반응만 유효 기간 안에 보관하고 낡은 cue를 뒤늦게 순차 재생하지 않는다.
- 응답 취소·공급자 전환·복구 snapshot·승인 대기는 기존 stale 차단을 유지한다. 의미 연기를 정리하고 중립으로 복귀하되 승인 입력 영역이나 저장한 배치는 움직이지 않는다.
- LLM의 답변/페르소나와 시각 preset을 맞추는 작업은 별도다. 앱이 세션 기억을 다시 쓰거나 공급자 간 이력을 옮기지 않는다.
- TTS 도입 시 입은 실제 음성 재생 clock에 맞춘다. 현재 텍스트 delta를 가짜 발화 립싱크로 취급하지 않는다. 이 조사에서 TTS 제공자/보이스를 선정하거나 호출하지 않았다.

### 권장 구현 순서와 수락 기준

1. **구동과 전환:** DeepSeek upstream 프로필, 범위/중립값 검증, expression crossfade·배타 규칙, pose 진입/유지/복귀를 먼저 만든다. 기존 자산의 실제 시각 의미를 수동 미리보기로 확인하고 `wave`와 의미가 다르면 매핑을 수정한다.
2. **기본 생동감과 핵심 연기:** 비주기 blink/작은 시선 변화, thinking/explain/shy/tease/success 프리셋을 기존 Jev 결과와 로컬 상태로 구동한다. 눈→고개→몸의 지연은 예컨대 0/80/180ms를 시작값으로 비교하되 모델/강도별로 조절한다. 이 수치는 관찰 영상의 실측치가 아니다.
3. **조작 가능한 구도:** 전신/상반신/근접 프리셋, 배치 잠금, 연출 강도, reduced motion, 호출형 표정/포즈 미리보기 패널. 자동 연기는 사용자 배치·잘림을 바꾸지 않는다. 특히 근접 연출의 canvas clipping과 alpha 입력 영역 갱신도 확인한다.
4. **대사와 연기의 리듬:** bounded attitude Choice와 문장 coalescing을 한국어 fixture로 검증한다. TTS/립싱크는 이 상태 머신 위에 별도 단계로 통합한다.

검증은 외부 AI 없는 local fixture로 중립→홍조→장난→중립, 설명 포즈 진입/유지/복귀, cancel/approval/전환을 반복하고 종료 후 잔류 parameter·자세 튐·눈 충돌을 확인한다. 순수 scheduler/blend는 fake clock으로, physics 입력 순서는 synthetic 모델로 검사한다. 30/60/120fps 시간 일관성, hover/드래그/휠 충돌, 부분 오프스크린 및 모니터 이동, click-through, 일시 구도 복귀와 기본 구도 재실행 복원도 수락 범위다. 비교할 때는 같은 fixture·같은 모델·같은 구도에서 현재/제안 녹화를 비교한다.

이번 조사는 구현 변경 없이 소스/JSON과 공개 영상 프레임을 비교했고 관련 기존 unit test 35개를 실행해 통과했다. 새 연출의 시각 품질·성능·재실행 유지성은 아직 검증하지 않았다.

## 에이전트 전환 설계

- 전환 전에 '기존 요청이 계속 실행 중' 여부를 표시.
- 미완료 요청은 탭 내에 남기며 새 에이전트 대화에 합쳐지지 않음.
- voice/model override는 `per-agent` 또는 `global`로 선택; 미설정 시 글로벌로 fallback.
- 특정 봇의 이름·아이콘은 실제 공급자 표시와 매핑, 존재하지 않는 봇의 기억을 있는 것처럼 표현하지 않음.
- capability 불일치(예: Grok 비동기, 이미지 미지원)는 전환 화면에서 노출.

## 승인 및 프라이버시 UX

스크린샷 전송 버튼은 **선택 → 미리보기 → 전송 확인** 단계를 따른다. 수신 에이전트와 캡처 영역을 표시. PC 도구 승인 UI는 행동/대상/예상 영향/기한, '이번 한 번 허용'과 '거절'을 제공하며 임의 광범위 영구 허용 버튼은 초기 버전에 만들지 않는다.

## 접근성

- UI 글자 크기, 대비, 키보드 탐색, ESC 닫기, 단축키, 발화 자막 지원.
- reduced motion, 음소거, 알림 끄기, 포커스 복구 제공.
- 눈에 띄는 연결 오류와 재설정 안내, 음성만으로 상태 알리지 않음.

## 반응 우선순위

`approval/security > user interaction > speech playback > tool execution > thought > idle`. 단일 모션 슬롯으로만 구현 가능한 모델에서도 안전 상태가 우선한다.

### 메시지 연기와 작업 상태 우선순위 (2026-11-01)

텍스트가 도착하는 동안 도구 작업이 없으면 기본 연기는 idle이다. waiting의 thinking과 도구 실행의 working은 배경 상태이고 메시지의 한 번짜리 반응을 덮어쓰지 않는다. 메시지 반응 중에는 배경 생각 고개·시선을 섞지 않으며, 표정과 손 포즈가 자연스럽게 끝난 뒤 최신 작업 상태로 돌아간다. 이는 음성 talking/립싱크 구현이 아니다. 새 요청·선택 변경은 이전 반응을 초기화하며, 승인·재연결 상태 확인·취소·오류는 즉시 표현을 정리한다.

### 설명 제스처의 사용 범위 (2026-11-01)

답변에 정보·기술 용어·목록이 있다는 이유로 손가락 설명 포즈를 고르지 않는다. 일상 대화·진행 확인·결과 보고는 `gesture=none`을 기본으로 두고, 예제나 차이를 직접 짚으며 가르치는 명확한 순간에만 `explain`을 선택한다. 설명하는 말투와 손 제스처는 독립적이다. `attitude=explain`이어도 `gesture=none`이면 가벼운 고개·시선 연기만 하고 손을 들지 않는다. 명시적 설명 제스처와 설정의 설명 미리보기는 기존 진입/유지/복귀를 사용한다.

중립/제스처 없음은 정지하라는 뜻으로 쓰지 않는다. 메시지 ID가 있는 중립 cue에는 1.8초짜리 로컬 전달 반응(`acknowledge`)을 사용한다. 알아볼 수 있는 끄덕임·좌우 교대 기울임과 눈썹 반응만 넣고 감정/손 포즈/입 움직임은 추가하지 않는다. 중복 ID는 반복하지 않고 다음 실제 메시지는 바로 반응하며, 승인·취소·재접속 차단은 즉시 정리한다. Jev Choice나 외부 호출을 추가하지 않고 neutral/none의 의미도 유지한다.

### 채팅과 설정 창 분리 (2026-11-01)

채팅은 캐릭터 이름·대화·입력과 필요한 작업 상태/오류/승인 조작만 표시한다. 환영 장문, 연결 상세, Jev 표현 진단과 설정 성공 안내를 상시 노출하지 않는다. 연결의 미지원/연속성 한계·Jev 전송 범위·보호 저장소 상태는 설정에 둔다. ⚙/트레이에서 설정을 별도 floating 창으로 열고 재호출은 기존 창을 포커스한다. 설정을 열고 닫아도 채팅을 숨기거나 reload하지 않고 입력 초안·대화·스크롤을 유지한다. 설정 저장/세션 변경은 기존 main coordinator에 반영하고 채팅을 동기화한다.

### 고개 반응 가시성 (2026-11-01)

고개 반응의 가시성은 전체 모델 상하 이동을 키우지 않고 회전축의 진폭과 추종 속도로 조절한다. `acknowledge`는 headY 목표 -0.48, 명시적 `nod`는 ±0.60, `shake`는 ±0.52이며 강도·시간 envelope·보정을 거친다. 기본 4.5/s였던 고개 추종은 끄덕/도리도리에서 8.5/s, 중립 전달/안심에서 6.5/s를 사용한다. 안심의 끄덕임은 ±0.36으로 구분하며, 중립 감정이나 제스처 none을 손 포즈로 승격하지 않는다.

### 입력창 명령 (2026-11-01)

`/`에서 짧은 명령명/라벨만 목록으로 표시한다. `/new`는 현재 연결/프로필의 일반 새 대화, `/settings`는 별도 설정 창, `/stop`은 현재 요청 중단, `/status`는 상태 조회, `/help`는 목록이다. 목록은 ↑/↓·Home/End·Tab·Enter·Esc로 조작하며 한글 조합/Shift+Enter는 기존 입력을 유지한다. 명령은 에이전트의 자연어 답변이나 실행 권한으로 해석하지 않고 사용자가 composer에서 제출했을 때만 기존 IPC를 호출한다. 생성 대기 중 입력을 새로 쓰면 완료 후 그 초안을 보존한다. 다른 창의 미저장 설정을 밀어내거나 세션 ID를 되돌리지 않도록 선택 메타데이터만 동기화한다.

### 앱 식별과 실행·세션 전환 (2026-11-01)

앱·런처·창 제목·트레이는 Live2D Companion, assistant 라벨은 COMPANION으로 표시한다. 제공된 Live2D 모델의 파일/제작자 이름과 연결한 모델 공급자는 설정/기술 문서에서 별도로 다룬다. rofi의 drun 항목은 개발 checkout의 로컬 Electron을 직접 실행하고 같은 userData의 재실행은 기존 채팅을 표시한다. 새 세션 생성은 대화 binding만 바꾸며 renderer reload로 캐릭터를 잠깐 숨기지 않는다. 새 binding은 이전 반응을 reset하고 같은 모델/캔버스·physics/runtime을 유지한다.

### Kitty 기준 채팅·설정 (2026-11-01)
