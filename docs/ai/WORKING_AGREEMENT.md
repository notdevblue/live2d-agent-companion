# AI 개발 작업 규약

## 목적

Codex, Claude Code 및 기타 에이전트가 프로젝트 의도와 안전 경계를 놓치지 않고 기능을 구현하도록 하는 작업 계약. 이 파일은 **AI에게 주는 지속 지침**이며 제품 기능 명세를 대체하지 않는다.

## 우선순위 및 충돌

1. 사용자 최신 명시 지시와 상위 안전/보안 요구사항.
2. 승인된 ADR 및 `docs/architecture/SECURITY_PRIVACY.md`.
3. `docs/specs/`의 테스트 가능한 MUST 요구사항.
4. `docs/product/PRD.md`의 범위 및 단계.
5. `docs/architecture/`의 설계 계약.
6. 통합 문서의 검증된 사실, 그 외 제안 사항.

서로 모순되면 스스로 조용히 변경하지 말고 영향과 대안을 PR에 기록한다. 공식 공급자 문서는 최신 버전을 다시 확인하고 잠정 제안과 구별한다.

## 반드시 지킬 것

- 작업 전에 영향을 받는 문서, 코드, 테스트, 공식 자료를 읽는다.
- Grok에는 자료 조사·근거 정리만 맡긴다. 코드 설계·구현·반영은 메인이 담당하며, 조사 의견은 기존 코드와 실제 모델 검증을 거쳐 채택한다.
- Grok Bot **기존 Bot**과 xAI **모델 API**는 별개의 대상이다. 기존 Bot 연결 실패를 모델 API로 조용히 우회하지 않는다.
- Hermes **일반 세션**, **프로필**, **Bot Mode의 영구 Bot Chat**을 구분한다.
- 공급자/세션 키는 복합 식별자를 사용한다. 단순한 Bot 이름만으로 대화 이력을 합치지 않는다.
- 사용자에게 보이는 메시지 텍스트만 TTS 대상으로 삼는다. 비밀값, chain-of-thought, 도구 로그, 오류 스택을 음성 출력하지 않는다.
- 에이전트가 생성한 텍스트를 실행 권한으로 간주하지 않는다.
- 클릭·타이핑·프로세스 실행·파일 변경은 제안 단계와 실제 실행 단계를 분리한다.
- 스크린샷 수집은 명시적 요청과 유효한 범위 선택 후에만 수행한다. 무음/상시 촬영은 기본 비활성화.
- 토큰·웹훅 키·개인 세션·스크린샷·상용 모델 파일을 저장소에 커밋하지 않는다.
- 불확실한 API 필드/메서드는 Mock과 Spike로 확인하고, 확인 전 프로덕션 구현에 단정적으로 사용하지 않는다.

## 작업 보고서 형식

1. 목표·수정 파일·요구사항 ID
2. 근거(공식 문서/기존 코드/테스트)
3. 구현한 항목과 미구현 항목
4. 실행한 검사 및 결과, 실행 불가 이유
5. 안전·성능·호환성 영향
6. 남은 리스크와 다음 과제

## Definition of Done

- 최소 단위 테스트, 계약 테스트 및 단계별 관련 수락 기준 통과
- 실패·취소·재시작·오프라인·권한 거절 경로 확인
- 사용자 승인 없는 PC 도구 실행 경로 없음
- 문서·변경 로그/ADR·테스트 업데이트
- 확인되지 않은 주장을 제거하거나 `Spike-required`로 표시
