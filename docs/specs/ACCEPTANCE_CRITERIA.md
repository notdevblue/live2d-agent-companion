# 수락 조건 (Given / When / Then)

프로젝트 전체의 수락 기준이다. 구현된 부분과 미검증 부분은 [IMPLEMENTATION_STATUS](../development/IMPLEMENTATION_STATUS.md)에서 구분한다. 통합 테스트 환경·재현 단계·결과 링크를 충족해야 해당 항목을 완료 처리한다.

## AC-01 데스크톱 창 (`FR-UI-001~003, 005`)

- **Given** Windows 11 + 검증된 Live2D 샘플, **When** 앱을 실행하면, **Then** 투명 배경의 캐릭터가 렌더되고 드래그·채팅 입력이 가능하다.
- 모델 파일이 없으면 크래시하지 않고 선택 안내를 표시한다.
- 캐릭터 우클릭·트레이 설정 및 채팅 `/settings`는 별도 non-modal 설정 창을 한 개만 열며, 재호출은 기존 설정 창을 포커스한다. 채팅은 동시에 표시·입력 가능하고 설정 닫기/재열기에 transcript DOM·입력 초안·스크롤을 유지한다. 설정 창은 메시지 전송/승인/중단 IPC를 실행하지 못한다. 프로필/세션 변경은 채팅에 동기화하고 늦은 bootstrap이 새 선택을 되돌리지 않는다.
- 채팅에는 환영 장문·Bot Chat 상세·Jev 표현 상태·설정 성공 안내가 없다. 연결 상세와 Jev의 전송 범위/자격증명 상태는 설정에서 표시하며 채팅 오류/승인/복구·중단은 유지한다.
- 캐릭터 우클릭은 트레이와 동일한 native 메뉴(채팅·설정·캐릭터 위치 복구·종료)를 연다. 빈 영역·드래그 중에는 열지 않고 왼쪽 클릭/드래그를 유지한다. 우클릭 자체는 채팅을 열거나 위치를 바꾸지 않는다. 메뉴 IPC는 Overlay만 허용하며 채팅/설정 renderer 호출은 거절한다. 위치 복구는 트레이·우클릭·단축키가 같은 경로를 사용하고 복구 위치를 저장한다.
- 평소에는 모델만 보이고 사각 배경·창 테두리·제목 표시줄·상시 조작 패널이 보이지 않는다. 채팅/설정은 사용자 호출 시 별도 창으로 열린다.
- Linux/Sway Xwayland에서 채팅·설정 창은 포커스 가능한 floating 창으로 열린다. 최초 생성·닫고 다시 열기·앱 재실행 후에도 적용되며 모델 Overlay의 항상 위 동작은 유지한다.
- DeepSeek 표정·모션 목록에는 한국어 표시명을 제공하고 원문은 tooltip으로 확인한다. 매핑 선택·저장값은 원래 자산 ID를 사용하며 번역이 없는 이름은 원문으로 표시한다.
- 채팅에는 상단 로고·앱 이름·설정 아이콘이 없고 설정 호출은 우클릭/트레이/명령으로 제공한다. 짧은 말풍선은 내용 너비를 사용하고 메시지 간격·안쪽 여백을 줄인다. 한 줄 입력은 최대 120 CSS px까지 자동으로 늘어나며 전송/첨부 버튼을 가리지 않는다. 현재 Kitty 기준 Ubuntu Mono 11pt·D2Coding, #1E191F/#E1DBD1/#88D4CC와 Linux 배경 alpha .8을 사용하고 글자·버튼의 전체 opacity는 낮추지 않는다.
- 팝업의 Yuru 테마는 대화/설정/승인/폼 컨트롤에 일관되게 적용되고 470×810 및 최소 400×600에서 수평 잘림 없이 설정을 스크롤할 수 있다. 모델 Overlay는 alpha 0인 빈 영역을 유지한다. 창 재생성/앱 재실행 후에도 테마·floating이 유지되며 OS 재로그인 검증과 구분한다.
- `FR-UI-002`: 첨부/전송 버튼은 32×32px, 내부 SVG는 18×18px이며 한 줄 textarea도 32px로 중심을 맞춘다. 여러 줄에서는 마지막 줄과 버튼 하단을 맞추고 상태/중단은 동일한 20px 줄·11px 글꼴을 사용한다. 설정의 입력/select/일반 버튼은 32px로 정렬하며 hidden 조작은 표시하지 않는다.
- `FR-UI-002`: 입력칸 포커스 표시는 composer 경계에 적용하고 전송 버튼과 겹치지 않는다. 470×810·400×600·640×900 및 125% 확대에서 긴 대화는 conversation 내부만 스크롤되며 footer/전송 버튼이 보이고, 상태 문구는 줄바꿈할 수 있다. 답변 bubble은 불필요한 오른쪽 여백 없이 가용 폭을 사용한다.
- 모델 이동·배율·경로 설정을 저장하고 앱 종료/재실행 후 복원한다. 모니터 제거·DPI 변경 뒤 화면 밖에 남으면 복구할 수 있다. 이 항목은 실제 Windows 실행 기록으로 검증한다.
- 클릭 통과를 지원한다고 표시하려면 빈 영역의 클릭이 뒤 앱에 전달되고 모델 위 클릭/드래그는 정상이며, 드래그 중 끊김·모델 재진입 실패가 없는지 검증한다. 승인 창에는 클릭 통과가 적용되지 않는다.
- Linux X11/Xwayland에서는 클릭 통과 후 모델 재진입과 드래그 capture 취소를 검사한다. native Wayland에서 지원되지 않는 입력 기능을 지원으로 표시하지 않는다. Sway의 항상 위/모든 작업공간 표시는 실제 창 생성 방식과 앱 재실행을 확인하고 Windows 검증과 구분한다.
- 왼쪽 드래그 중 휠을 사용하면 배율이 0.4~4배 범위에서 바뀌고 화면 가장자리에서도 잡은 지점을 유지한다. 설정 슬라이더와 저장 검증도 같은 범위다. 큰 창/높은 DPI에서는 canvas를 GPU dimension·기존 readback 예산 안으로 줄여 입력 영역 계산이 전체 사각형 fallback으로 빠지지 않게 한다. 모델 재로딩·원격 요청 없이 조절하며 배율 조절 후 버튼을 놓아도 채팅이 열리지 않는다. 위치와 배율은 앱 재시작 후 유지한다.
- 화면 경계 보정은 모니터 사이 드래그와 의도적인 부분 표시를 막지 않는다. 하반신을 화면 아래로 내보낸 뒤 버튼을 놓고 재실행해도 그 위치를 유지한다. 모든 모니터에서 완전히 벗어난 창과 모니터 제거 뒤 사라진 창은 복구한다. 항상 위·모든 작업공간 표시 선택은 별도로 유지한다.
- 설정의 모니터 목록은 연결된 화면의 이름/크기·현재 화면을 표시한다. 선택 이동은 위치만 저장하고 대화 대상/세션/진행 중 요청·모델 배율을 변경하지 않는다. 사라진/알 수 없는 모니터 ID는 거절한다.

- Linux 런처는 사용자 applications/bin/icon 경로에 영구 설치하며 desktop-file-validate·wrapper 구문을 검사한다. rofi drun의 Live2D Companion으로 시작하고 재호출해도 같은 primary PID와 Overlay 한 개를 유지하며 기존 채팅을 표시한다. 노출명은 앱 이름으로 통일하고 특정 모델 공급자명을 앱 정체성으로 사용하지 않는다.
- `/new`는 동일 Overlay window/webContents process/canvas·로딩 상태와 증가하는 frame count를 유지한다. 이전 반응/손 포즈는 중립으로 정리하며 매핑/실제 모델/생성 옵션 변경의 필요한 reload와 구분한다.
- `/` 입력은 명령 목록을 열고 ↑/↓·Home/End 선택, Tab 완성, Enter 실행, Esc 닫기를 제공한다. 한글 조합/Shift+Enter는 실행하지 않으며 반복 Enter·진행 중 명령의 중복 실행을 막는다. `/new`는 현재 프로필의 기존 새 세션 API를 사용하고 명령을 user bubble·remote prompt·Jev에 넣지 않는다. 생성 대기 중 새로 쓴 초안은 지우지 않는다. `/settings`는 별도 창을 열고, `/stop`·`/status`는 현재 요청 ID를 사용한다. 알 수 없는 단독 명령/지원하지 않는 인자는 입력을 남겨 안내하고 `/etc/os-release` 같은 경로형 일반 입력은 유지한다.
- 채팅의 `/new` 뒤 열린 설정 창의 미수정 session 필드와 저장 기준을 갱신한다. 설정에서 작성 중인 다른 값은 보존하며 이후 표현 설정 저장이 이전 세션으로 되돌리지 않는다. 이전 선택의 느린 전송/설정 조회 완료가 새 대상의 입력·요청 상태를 덮지 않는다.

## AC-02 에이전트 상태 (`FR-AG-001~004, 010, 012`)

- Hermes와 Grok(실험적) 설정의 선택·연결 상태·지원 capability를 각각 표시한다.
- 전송 요청 중 네트워크가 끊기면 성공으로 바꾸지 않고 오류·대기·재시도 유의사항을 표시한다.
- 이전 에이전트의 지연 콜백이 현재 에이전트 음성/UI에 섞이지 않는다.
- **Given** 응답 중 연결만 끊김, **When** 기존 원격 실행에 재접속, **Then** 요청은 `reconciling`을 거쳐 복구되고 최종 결과는 원래 request_id에 한 번만 반영된다. 복구 전 같은 세션의 새 제출은 차단된다.
- 30초 무이벤트/연결 끊김과 앱 재시작 복원은 원래 요청을 자동 조회한다. 원격 진행이 확인되면 감시를 이어가고 완료 결과는 한 번 반영한다. replay가 만료돼도 receipt와 살아 있는 승인 snapshot을 확인한다. 조회 불가 시 최초 조회와 1/2/4/8/16초 backoff 재시도 후 수동 확인을 안내하고 lease를 유지한다. 자동 재전송·취소·승인과 중복 조회는 없다. 종결·dispose 뒤 타이머가 남지 않는다.
- 확인된 승인 대기 중에는 일반 무이벤트 타이머가 승인을 방해하지 않는다. 기존 승인 만료 뒤 감시를 재개하며 승인 유효기간을 연장하지 않는다. 원격 종료가 확인되면 lease를 해제하고 복구된 과거 본문의 Jev/연출은 재실행하지 않는다.
- 종료가 확인된 실패 요청을 사용자가 재전송하면 같은 turn_id와 새 request_id를 사용한다. 과거 요청의 지연 결과가 새 요청을 완료시키지 않는다.
- Mock에서 비스트리밍 최종 응답, 승인 거절·철회, 중복 terminal, 복구 snapshot을 재현한다. snapshot은 본문을 중복 추가하거나 자동 발화하지 않는다.

## AC-03 Hermes (`FR-AG-005~007, 013`)

- `FR-CHAT-003`: 파일 선택·채팅 드롭·이미지/파일 paste는 전송 전 초안에 파일명·크기·허용 이미지의 blob 미리보기·삭제를 제공하며 일반 텍스트 paste는 그대로다. 첨부만 보내기·읽기 중 차단·삭제/선택 전환 후 늦은 읽기 무시·전송 중 다음 초안/추가 파일 보존·오류 시 원래 초안 보존을 검사한다. slash 명령과 첨부 혼용은 실행하지 않는다.
- `FR-CHAT-003`: main은 chat sender/selection을 확인하고 실제 바이트·파일명·개수/용량을 검증한다. Overlay/설정의 첨부 전송과 경로 주입은 거절한다. SSH chunk 크기·순서·SHA256·임시 파일 권한·symlink 방어·실패/중단 정리와 지원하지 않는 연결을 검사한다. 이미지와 일반 파일이 실제 Hermes 응답에서 각각 읽혔다는 근거가 있어야 실제 전달 완료로 표시한다. 앱 재시작 후 별도 설정 저장 없이 지원 기능이 자동 조회되며 기존 설정·세션·위치를 보존한다.

- `FR-UI-002/FR-CHAT-002`: 사용자가 이전 기록을 읽고 있다가 전송하면 새 입력이 보이는 하단으로 이동한다. 하단에서 답변이 길어지면 계속 추적하고 위로 스크롤하면 위치를 유지한다. 실시간/복원 답변의 굵게·목록·fenced code·표가 렌더링되며 사용자 입력의 Markdown은 원문이다. HTML/링크/이미지는 실행·이동·외부 fetch를 만들지 않는다. 작은 창/125% 확대에서 긴 코드/표의 내부 스크롤과 footer 표시를 검사한다.

- `FR-CHAT-001`: 같은 SSH session에서 채팅창 닫기/재열기·renderer reload·앱 재실행 후 사용자/assistant 기록이 순서대로 복원되고 답변 bubble이 중복되지 않는다. 세션을 바꾸면 기록을 격리하고 돌아오면 해당 기록을 복원한다. 복원 자체의 prompt/Jev 호출은 0회다. 재시작한 pending 요청은 원래 lease로 복구하고 종결 후 표시용 기록을 재조회한다. 읽기 실패는 오류를 보이며 다른 세션을 만들거나 재전송하지 않는다.

- SSH의 ‘새 대화’는 선택한 프로필의 일반 세션을 생성하며 `toolsets: []`로 파일/터미널 도구를 누락시키지 않는다. 생성/재선택/앱 재실행 뒤 같은 session ID를 사용한다. 원격 file 도구와 로컬 PC 파일 권한은 구분한다. 실제 공급자 smoke는 일반 대화에 제출하기 전에 전용 테스트 세션 여부를 검사한다.
- 실제 Hermes가 메시지 델타를 보내면 순서대로 표시하고 최종 결과 한 번만 확정한다.
- 승인 요청 시 실행을 멈추고 정확한 대상/동작을 표시하며 거절이 실제 거절로 전달된다.
- 특정 Hermes Bot의 기존 Chat을 선택했으면 리로드 이후 동일 Bot Chat에 대화가 이어지는지 검증; 확인 실패 시 기능을 미지원/경고로 표시.
- 승인 응답은 원래 binding/turn/request/approval에만 전달된다. 만료·서버 철회·이미 처리된 승인 및 타 요청에 대한 응답은 재적용하지 않는다.
- 응답 전송 후 연결이 끊겨 적용 여부가 불명확하면 성공으로 표시하거나 자동 재전송하지 않는다. 재접속 시 살아 있는 요청만 복원하고 로컬 PC 권한은 발행하지 않는다.

## AC-04 Grok Bot (`FR-AG-008, 009`)

- Webhook 200 수신 시 상태는 `accepted/awaiting_result`이며 완료가 아니다.
- 유효한 Callback(구현·공급자 지원 확인 시)에서만 `completed`로 전환.
- 유효하지 않은 인증/중복/일치하지 않는 request_id는 거절하며 사용자 텍스트에 노출되지 않는다.
- 특정 **기존** Grok Bot의 기억/대화 연속성을 입증하지 못하면 이를 제공한다고 광고하지 않는다.

- 새 인벤토리의 기쁨은 파일 없는 기본 연기로 웃고 `happy + laugh`는 절차 눈을 감는다. 저장한 `＞＜` 매핑은 그대로 복원되어 강조 중 특수 눈이 우선한다. 기본값 변경이 사용자 설정을 마이그레이션하지 않는다.
- `embarrassed + laugh`는 홍조와 절차 눈웃음이 공존한다. `concerned + tease`는 식은땀과 선택한 장난 눈이 공존한다. 눈은 한 종류만 자동 선택하고 홍조·땀·눈물은 서로 다른 키로 함께 올릴 수 있다. 자동 보조 표정에는 옷·소품을 넣지 않으며 사용자의 직접 자산 매핑은 보존한다. 각 층과 같은 이름의 파라미터 구성이 바뀌어도 240ms crossfade가 이어진다.
- 설명/인사 손은 authored 진입을 완료한 뒤 강세→약간 낮춘 유지→유한한 부분 올림→복귀를 진행하고 같은 의미 반응의 유한 수명 안에 복귀 클립을 끝낸다. 검증된 팔 입력 하나의 작은 offset만 사용하고 selector·손가락·소매 연결과 원본 복귀 endpoint를 보존한다. 복귀 뒤 selector·손목·손가락 endpoint가 중립이다. 새 메시지 첫 글자, 정정, 승인·취소·오류·초기화는 여운과 손을 정리하고 오래된 ID의 clear는 현재 반응을 지우지 않는다.
- 강도·움직임 줄이기를 여운 도중 바꾸어도 반응을 다시 시작하지 않고 즉시 줄인다. 움직임 줄이기는 손을 정리한다. 30/60/120fps, 없는 채널, authored motion 및 physics 출력 보호, 기존 상하 offset 한도와 Jev 판단 예산을 유지한다.
- 같은 모델·구도의 기쁨·장난·슬픔을 lean 계수 .35/.7로 비교하고, 기쁨·기쁨+웃음·부끄러움+웃음 및 설명/인사 손의 진입·유지·복귀를 실제 SDK로 렌더한다. 재현 명령·PNG·파라미터 결과는 구현 상태 문서에 연결한다. 이는 실시간 FPS 또는 TTS 동기 검사와 다르다.

### 추가 감정·쓰다듬기 (`FR-DIR-006`, `FR-L2D-008`)

- 감정 8종×말투 6종×제스처 4종의 범위·만료·차단을 검사한다. `angry`/`confused`의 판단/확신도는 다른 채널과 독립 검증하고 같은 Jev 요청의 enum을 사용한다. 화자 분노·혼란, 감정 주제의 사실 설명, 화난 사용자에게 위로, 차분한 숙고를 합성 대조한다. 실제 API 대조와 모의 transport 검증을 구분한다.
- 화남은 지원되는 음수 입 형태·눈썹·삐죽·볼을 실제 범위로 구동하고 physics/authored 채널은 생략한다. 화남·혼란의 여운은 닫힌 입이다. 혼란의 특수 눈은 다른 눈 아트와 배타이며 절차 눈과 충돌하지 않는다. 없는 자산에서도 고개/시선 연기가 동작한다. 신규 매핑 행의 저장·복원·빈 선택을 strict schema로 검사한다.
- 로컬 미리보기 20종은 enum/실제 버튼/요청·승인 차단과 일치하며 외부 판단을 하지 않는다.
- 쓰다듬기는 기본 꺼짐이며 켜기·끄기가 저장/renderer reload/앱 재실행 뒤 복원된다. Shift+왼쪽으로 상단 실루엣을 문지를 때만 눈웃음·미소·작은 고개 반응이 나온다. 짧은 정지 클릭, 투명 영역·하단, 큰 포인터 점프에는 반응하지 않는다. 위치 잠금 상태에서도 쓰다듬을 수 있고 창 이동·휠 배율·채팅 열기는 발생하지 않는다.
- 멈춤/상단 이탈/Shift 해제/버튼 해제/캡처 취소/blur는 짧은 여운 후 복귀로 끝난다. 해제는 최대 .3초 유지+.75초 fade이며 최초 접촉의 12초 한도 안에 끝난다. 중복 종료 이벤트로 여운을 재시작하지 않고 지속 입력도 12초 안에 끝난다. 요청/승인·오류·설정 해제/초기화는 즉시 정리한다. 강도·움직임 줄이기, 특수 눈·authored/physics 채널 우선순위와 30/60/120fps 시간을 유지한다. 직접 입력 종료 후 기존 메시지 여운을 재판단·재시작하지 않는다.
- 접촉한 로컬 좌표의 좌/우·상/하가 고개·시선 방향에 반영되고 범위 밖·비유한 좌표를 제한한다. 잔여 반응이 없는 새 접촉은 이전 위치를 초기화한다. 복귀 도중 재접촉은 기존 방향·몸 반응을 보존하고 새 좌표로 연속 전환한다. 접촉 해제 후 방향 기여도 같은 envelope로 사라진다. 홍조는 사용자 `embarrassed` 자산의 안전한 표시만 사용하고 옷/소품·physics 출력·authored 채널을 넣지 않는다. 기존 홍조와 중복 가산하지 않는다.

- 유효한 위치/알파 적중의 누적 8px 직접 stroke에서만 검증된 원본 가슴 손 pair를 시작한다. 의미 `gesture=none`만으로 시작하지 않는다. 다른 손/기존 모션을 빼앗지 않고 사용자 custom/빈 매핑·움직임 줄이기·늦은 접촉·부족한 자산은 몸/얼굴만 반응한다.
- 손 진입 중 해제는 마지막 렌더 시각의 원본 진입을 역재생하고 hold 이후에는 원본 복귀를 쓴다. 해제 최대 1.05초·정지 .9초·최초 12초 안에 손과 몸이 끝난다. 정지 이벤트·중복 해제로 기한을 늘리지 않는다. 손이 복귀하는 중 새 접촉도 같은 기존 손 복귀와 기한을 유지한다.
- 재접촉 첫 프레임의 MVP·고개·눈이 초기값으로 튀지 않는다. 새 stroke 없는 반복 begin/end가 기존 몸 fade를 재활용해 연장하지 않는다. scoped 메시지 clear는 직접 접촉의 손/얼굴을 지우지 않고 새 cue/요청·승인·오류·설정 해제는 즉시 정리한다. 실제 SDK에서 조기 해제·정지·12초·custom/접근성·손 소유권·재접촉/무 stroke·scoped clear를 확인한다.

### Grok 시각 연기 검토 (`FR-L2D-009`)

- 손 없는 기쁨의 유지 얼굴은 밝은 열린 눈, 웃음은 한 번의 웃음 뒤 닫힌 입의 미소로 구분한다. 명시적인 유지 입 열림0이 공통 최소값에 덮이지 않고 neutral acknowledge의 기존 작은 입 목표·compound 감정·강도/움직임 줄이기·기한은 보존된다. 실제 SDK8초의 눈/입/입꼬리 차이를 확인한다.
- 대기 시선은 같은 불규칙 슬롯 안에서 눈이 먼저 이동하고 반대 방향으로 돌아올 때 고개·지연 상체는 측면 목표를 유지한다. 고개와 눈이 같은 감소 목표로 함께 복귀하는 것과 구분하고 실제 MOC 눈/머리 대조·범위·접근성·기존 Y/호흡/rootY를 확인한다.

- 걱정+장난은 약 .9초 준비 감정 뒤 wink를 내고 눈꺼풀과 idle-blink 억제가 같은 지연 시계를 쓴다. 화남의 눈은 유지 중 더 좁게 보이되 의미 반응·미리보기/delivery의 마지막 fade에서 중립으로 접근한다. 기한 직전까지 반쯤 닫혀 있다가 마지막 한 프레임에 열리지 않는다. 30/60/120fps·강도/접근성·clear/기한과 실제 SDK 종료 직전 값을 확인한다.

- 기존 불규칙 대기 시선 슬롯마다 눈→고개→지연 상체의 한 번의 수평 자세 이동을 제공하고 별도 반복 시계·상하 offset/호흡 증폭을 만들지 않는다. 순수 기쁨/웃음의 손 없는 반응은 1.85~3.7초의 한 번의 청자 확인 시선 뒤 약간 비스듬한 유지로 돌아오며 수줍음/명시적 손의 시계는 보존한다.
- 초기 기쁨/웃음은 기존 시계 안의 한 번의 몸 접근 뒤 안정하고, 화남은 옆으로 돌기→눈 재접촉 뒤 측면 자세/닫힌 입을 유지한다. 걱정 섞인 장난의 숙임→재접촉은 wink 시계를 보존한다. `gesture=none`에서 authored 팔 포즈를 만들지 않는다. 직접 접촉의 작은 접근도 같은 가중치로 해제하며 더 강한 기존 lean과 ambient offsetY/호흡을 보존한다. 실제 forward branch/physics 출력과 복귀를 SDK에서 확인한다.

- 대기 시선의 좌우 이동은 실제 rig의 고개 회전과 지연된 상체 호응으로 이어진다. 같은 불규칙 시계를 사용하며 고개/상체 범위를 강도·움직임 줄이기로 제한한다. SDK 수락 검사는 입력값뿐 아니라 physics 뒤의 `ParamAngleX`/`ParamBodyAngleX` 변화와 움직임 줄이기의 감소를 확인한다. 상하 offset·호흡·창 위치/배율을 이 변화의 대체 수단으로 키우지 않는다.
- 쓰다듬기의 접촉 방향은 반대 방향의 기존 시선/고개/상체보다 우선하고, 해제 가중치가 0으로 갈 때 음수 입 형태를 포함한 원래 감정으로 연속 복귀한다. 0 가중치는 원래 frame을 그대로 보존한다.

- 기쁨/대기, 걱정+장난/장난, 부끄러움+웃음/웃음의 얼굴·시선·고개 의도를 구별하고 실제 SDK 렌더로 확인한다. 부끄러움+웃음은 처음 시선을 피한 뒤 웃는다. 두 번째 변주는 후속 윙크뿐 아니라 강조의 시점/길이도 달리한다.
- 특수 눈 층의 자체 기한과 복귀를 검사한다. 기한이 끝난 눈은 사라져도 홍조/땀의 의미 여운은 유지한다. 저장된 특수 눈 선택과 빈 매핑은 바꾸지 않는다.
- 특수 눈의 서로 다른 그림은 crossfade 중에도 하나만 표시한다. 전환의 중간 가중치에서 표시 소유권을 넘겨 회색/이중 홍채의 합성을 피한다. 사용자의 자산 내 값은 보존하고 홍조/땀·연속 얼굴 입력은 기존 fade를 유지한다. `concerned + tease`의 두 번째 변주에서도 감정 합성이 한쪽 눈의 강조를 덮지 않는다.
- 설명/인사 유지 중 얼굴·시선의 움직임과 손 복귀 전 반응을 확인한다. 검증된 원본 클립의 실제 종착 자세를 의미 이름만으로 손 흔들기라고 가정하지 않는다. 새 인사의 입력·복귀는 기본 사용 경로에서 실제 모델 범위와 endpoint를 확인한다.
- 같은 모델/구도/강도/입력으로 고정 before와 각 회차 after를 렌더하고 소스 해시·타임라인을 기록한다. 새 Grok 세션에 목표 점수/이전 점수를 주지 않고 연기 기여도 단독은 같은 다섯 항목으로 평가받는다. 기존 아트를 포함한 전체 VTuber/캐릭터 매력의 종합 평가는 별도로 표시하고 서로 다른 기준의 점수를 상승 수치로 합치지 않는다. 평가자가 읽은 프레임과 한계, 점수/조치/재검토 결과는 [검토 문서](../ux/GROK_VTUBER_REVIEW.md)에 기록한다. TTS 부재나 테스트 수를 점수 근거로 쓰지 않는다.

## AC-06 화면 캡처 (`FR-SCR*`)

- 명시적으로 선택한 창/영역만 미리보기에 나타난다.
- 사용자가 최종 공유를 취소하면 캡처 바이트가 어느 공급자로도 송신되지 않는다.
- 이미지 미지원 공급자 선택 상태에서 송신 버튼이 비활성화된다.

## AC-07 도구 승인 (`FR-PC*`)

- 승인 없는 클릭/타이핑/명령 실행은 **0건**.
- 승인 대화상자는 요청 대상·행동·유효기간·위험을 설명하고, 다른 요청으로 재사용되지 않는다.
- 긴급 정지 버튼으로 진행 중인 자동 작업이 중단된다. 되돌릴 수 없는 작업은 별도 경고가 나온다.
